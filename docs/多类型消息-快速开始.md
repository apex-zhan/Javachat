## 🚀 核心方案（5分钟版）

### 问题
IM系统需要支持10+种消息类型（文本、图片、视频、语音...），如何优雅实现？

### 方案
**策略模式 + 工厂模式 + 模板方法模式**

```java
// 1. 抽象Handler（模板方法）
public abstract class AbstractMsgHandler<Req> {
    @PostConstruct
    private void init() {
        MsgHandlerFactory.register(getMsgTypeEnum().getType(), this);  // 自动注册
    }
    
    @Transactional
    public Long checkAndSaveMsg(ChatMessageReq request, Long uid) {
        Req body = toBean(request.getBody());
        checkMsg(body, request.getRoomId(), uid);  // 子类扩展校验
        Message msg = buildMsg(request, uid);
        messageDao.save(msg);
        saveMsg(msg, body);  // 子类扩展保存
        return msg.getId();
    }
    
    protected abstract void saveMsg(Message msg, Req body);
    public abstract Object showMsg(Message msg);
}

// 2. 具体Handler（策略）
@Component
public class TextMsgHandler extends AbstractMsgHandler<TextMsgReq> {
    @Override
    protected void saveMsg(Message msg, TextMsgReq body) {
        msg.setContent(sensitiveWordBs.filter(body.getContent()));  // 敏感词过滤
        messageDao.updateById(msg);
    }
    
    @Override
    public Object showMsg(Message msg) {
        return new TextMsgResp(msg.getContent());
    }
}

// 3. 工厂获取Handler
AbstractMsgHandler handler = MsgHandlerFactory.get(type);
Long msgId = handler.checkAndSaveMsg(request, uid);
```

### 数据库设计
```sql
CREATE TABLE `message` (
  `id` BIGINT AUTO_INCREMENT,
  `type` INT NOT NULL,  -- 消息类型：1文本 2撤回 3图片...
  `content` VARCHAR(1024),  -- 通用内容
  `extra` JSON,  -- 扩展字段（不同类型特有属性）
  PRIMARY KEY (`id`)
);
```

### 核心优势
- ✅ 新增类型：只需加一个Handler类（5分钟）
- ✅ 核心代码：完全不需要修改
- ✅ 代码复用：80%+（模板方法）
- ✅ 自动注册：@PostConstruct自动装配

### Step 3：定义DTO（2分钟）

@Data
public class LocationMsgDTO implements Serializable {
    private Double latitude;
    private Double longitude;
    private String description;
    private String mapSnapshotUrl;  // 地图快照

### Step 4：扩展MessageExtra（30秒）
```java
public class MessageExtra {
    private LocationMsgDTO locationMsgDTO;  // ✅ 新增
}
```

### Step 5：创建Handler（10分钟）
```java
@Component
public class LocationMsgHandler extends AbstractMsgHandler<LocationMsgReq> {
    
    @Override
    MessageTypeEnum getMsgTypeEnum() {
        return MessageTypeEnum.LOCATION;
    }
    
    @Override
    protected void checkMsg(LocationMsgReq body, Long roomId, Long uid) {
        // 校验坐标范围
        AssertUtil.isTrue(body.getLatitude() >= -90 && body.getLatitude() <= 90, "纬度错误");
        AssertUtil.isTrue(body.getLongitude() >= -180 && body.getLongitude() <= 180, "经度错误");
    }
    
    @Override
    protected void saveMsg(Message msg, LocationMsgReq body) {
        LocationMsgDTO dto = LocationMsgDTO.builder()
            .latitude(body.getLatitude())
            .longitude(body.getLongitude())
            .description(body.getDescription())
            .build();
        
        Message update = new Message();
        update.setId(msg.getId());
        update.setContent(body.getDescription());
        update.getExtra().setLocationMsgDTO(dto);
        messageDao.updateById(update);
    }
    
    @Override
    public Object showMsg(Message msg) {
        return msg.getExtra().getLocationMsgDTO();
    }
    
    @Override
    public Object showReplyMsg(Message msg) {
        return "[位置]" + msg.getContent();
    }
    
    @Override
    public String showContactMsg(Message msg) {
        return "[位置]" + msg.getContent();
    }
}
```

## 🎯 面试快速准备（10分钟版）

### 面试话术（STAR）

**问：介绍一下多类型消息的实现？**

> "【S】在IM系统中，需要支持10+种消息类型，传统if-else方案代码冗长、难维护。
> 
> 【T】我的设计目标是：单表存储、符合开闭原则、新增类型无需修改核心代码。
> 
> 【A】我采用了策略+工厂+模板方法模式：
> - 单表+JSON存储（type字段区分，extra存特有属性）
> - AbstractMsgHandler定义模板方法
> - 具体Handler实现不同类型的处理逻辑
> - @PostConstruct自动注册到工厂
> 
> 【R】最终核心代码从500行降至50行，新增类型只需5分钟，代码复用率80%+。"

### 追问准备

**Q1：为什么不用分表存储？**
> "我对比了分表和单表+JSON方案，分表需要UNION ALL查询、表太多、扩展困难。单表方案查询性能更好（<20ms）、扩展更容易。唯一缺点是extra字段不便于复杂查询，但可以通过ES解决。"

**Q2：策略模式和模板方法有什么区别？**
> "策略模式关注算法替换（运行时选择Handler），模板方法关注流程统一（编译期确定流程）。在项目中组合使用：模板方法定义流程，策略模式实现不同算法。"

**Q3：如何保证扩展性？**
> "通过开闭原则：新增类型只需加Handler，核心代码完全不动。@PostConstruct自动注册，泛型自动识别类型，无需手动配置。"

## 🔥 核心代码速查

### 发送消息流程
```java
// Controller
@PostMapping("/msg")
public ApiResult<ChatMessageResp> sendMsg(@Valid @RequestBody ChatMessageReq request) {
    Long msgId = chatService.sendMsg(request, uid);
    return ApiResult.success(getMsgResp(msgId));
}

// Service
public Long sendMsg(ChatMessageReq request, Long uid) {
    AbstractMsgHandler handler = MsgHandlerFactory.get(request.getMsgType());
    return handler.checkAndSaveMsg(request, uid);
}
```

### 展示消息流程
```java
public ChatMessageResp showMsg(Message msg) {
    AbstractMsgHandler handler = MsgHandlerFactory.get(msg.getType());
    Object body = handler.showMsg(msg);
    return ChatMessageResp.builder()
        .id(msg.getId())
        .type(msg.getType())
        .body(body)  // 多态：不同类型返回不同body
        .build();
}
```

## ⚡ 常见问题

### Q：支持哪些消息类型？
A：文本、图片、视频、语音、文件、表情、系统消息、撤回消息等10+种，可随时扩展。

### Q：性能如何？
A：消息列表查询<20ms，单表索引优化后性能稳定。

### Q：如何支持消息加密？
A：在AbstractMsgHandler的beforeSave钩子中加密，afterSave中解密。

### Q：如何支持消息搜索？
A：集成ElasticSearch，extra字段也可索引。
