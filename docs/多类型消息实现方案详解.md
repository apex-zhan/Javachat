## 一、STAR原则项目描述

### 🎯 **S - Situation（背景与问题）**

**业务背景：**
在IM系统中，用户可以发送多种类型的消息：
- 文本消息（支持@用户、URL识别、敏感词过滤）
- 图片消息（带宽高、URL）
- 视频消息（带封面、时长、大小）
- 语音消息（带时长）
- 文件消息（带文件名、大小）
- 表情消息
- 系统消息（入群、退群通知等）
- 撤回消息

**技术挑战：**
1. **如何优雅地处理10+种消息类型？**
   - 传统if-else：代码冗长、难以维护、违反开闭原则
   - 分表存储：表太多、JOIN复杂、扩展困难

2. **如何保证扩展性？**
   - 新增消息类型时，能否不修改核心代码？
   - 如何避免"改一处影响全局"的风险？

3. **如何统一处理流程？**
   - 保存、展示、回复、会话列表等多个场景
   - 每种消息类型的处理逻辑不同

---

### 🎯 **T - Target（设计目标）**

基于上述挑战，设计目标拆解为：

#### **目标1：单表存储 + 策略模式**
- 所有消息类型存储在同一张`message`表
- 使用`type`字段区分消息类型
- 使用`extra` JSON字段存储特有属性
- 避免表爆炸和JOIN查询

#### **目标2：符合开闭原则**
- 新增消息类型：只需新增一个Handler类
- 无需修改核心代码（Controller、Service）
- 实现"对扩展开放，对修改关闭"

#### **目标3：自动注册机制**
- Handler启动时自动注册到工厂
- 使用Spring的`@PostConstruct`特性
- 无需手动配置映射关系

#### **目标4：统一处理流程**
- 定义抽象模板：保存、展示、回复、会话列表
- 子类实现具体逻辑
- 保证流程一致性

### 2.2 数据库设计

#### **核心表结构：message表**

```sql
CREATE TABLE `message` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '消息ID（全局有序）',
  `room_id` BIGINT NOT NULL COMMENT '房间ID',
  `from_uid` BIGINT NOT NULL COMMENT '发送者ID',
  `content` VARCHAR(1024) COMMENT '消息内容（文本消息/图片URL/文件URL等）',
  `reply_msg_id` BIGINT COMMENT '回复的消息ID',
  `status` INT NOT NULL COMMENT '状态 0正常 1删除',
  `gap_count` INT COMMENT '与回复消息的间隔数',
  `type` INT NOT NULL COMMENT '消息类型 1文本 2撤回 3图片 4文件 5语音 6视频 7表情 8系统',
  `extra` JSON COMMENT '扩展字段（不同类型的特有属性）',
  `create_time` DATETIME(3) DEFAULT CURRENT_TIMESTAMP(3),
  `update_time` DATETIME(3) DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  PRIMARY KEY (`id`),
  KEY `idx_room_id` (`room_id`),
  KEY `idx_create_time` (`create_time`)
) ENGINE=InnoDB COMMENT='消息表';
```

#### **设计亮点：**

| 字段 | 作用 | 设计巧思 |
|-----|------|---------|
| **type** | 消息类型标识 | 通过type字段路由到不同的Handler |
| **extra（JSON）** | 扩展字段 | 存储各类型特有属性，避免冗余字段 |
| **content** | 通用内容 | 文本内容/图片URL/文件URL等 |
| **reply_msg_id** | 回复消息ID | 支持消息回复功能 |
| **gap_count** | 消息间隔数 | 优化回复跳转性能 |

**文本消息的extra：**

**图片消息的extra：**

```java
@AllArgsConstructor
@Getter
public enum MessageTypeEnum {
    TEXT(1, "正常消息"),
    RECALL(2, "撤回消息"),
    IMG(3, "图片"),
    FILE(4, "文件"),
    SOUND(5, "语音"),
    VIDEO(6, "视频"),

    SYSTEM(8, "系统消息");

    private final Integer type;
    private final String desc;

    // 缓存映射，提升性能
    private static Map<Integer, MessageTypeEnum> cache;
    
    static {
        cache = Arrays.stream(MessageTypeEnum.values())
            .collect(Collectors.toMap(MessageTypeEnum::getType, Function.identity()));
    }

    public static MessageTypeEnum of(Integer type) {
        return cache.get(type);
    }
}
```

**设计亮点：**
- ✅ 枚举类型安全，避免魔法数字
- ✅ 静态缓存Map，避免重复创建
- ✅ `of()`方法快速查找

## 三、核心设计模式详解

### 3.1 设计模式组合

本方案综合运用了以下设计模式：

| 设计模式 | 应用场景 | 核心作用 |
|---------|---------|---------|
| **策略模式** | 不同消息类型的处理 | 封装算法族，可互相替换 |
| **工厂模式** | Handler的获取 | 解耦创建逻辑 |
| **模板方法模式** | 统一处理流程 | 定义算法骨架 |
| **依赖注入** | Spring自动装配 | 降低耦合度 |

---

### 3.2 策略模式（Strategy Pattern）

#### **模式定义：**
> 定义一系列算法，把它们一个个封装起来，并且使它们可以相互替换。策略模式让算法的变化独立于使用算法的客户。

#### **类图：**

```
┌─────────────────────────────────────┐
│      AbstractMsgHandler<Req>        │  抽象策略
│  ┌───────────────────────────────┐  │
│  │ + checkAndSaveMsg()           │  │  模板方法
│  │ # checkMsg()                  │  │  钩子方法
│  │ # saveMsg()                   │  │  抽象方法
│  │ + showMsg()                   │  │  抽象方法
│  │ + showReplyMsg()              │  │  抽象方法
│  │ + showContactMsg()            │  │  抽象方法
│  └───────────────────────────────┘  │
└─────────────────┬───────────────────┘
                  │ 继承
        ┌─────────┴─────────┬─────────┬─────────┐
        │                   │         │         │
┌───────────────┐  ┌────────────┐  ┌─────────┐  ...
│TextMsgHandler │  │ImgMsgHandler│  │VideoMsg │
│               │  │             │  │Handler  │
└───────────────┘  └────────────┘  └─────────┘
   具体策略1          具体策略2       具体策略3
```

#### **核心代码：**

**抽象策略（AbstractMsgHandler）：**
```java
public abstract class AbstractMsgHandler<Req> {
    @Autowired
    private MessageDao messageDao;
    private Class<Req> bodyClass;

    // Spring启动时自动调用
    @PostConstruct
    private void init() {
        // 1. 通过反射获取泛型类型
        ParameterizedType genericSuperclass = 
            (ParameterizedType) this.getClass().getGenericSuperclass();
        this.bodyClass = (Class<Req>) genericSuperclass.getActualTypeArguments()[0];
        
        // 2. 自动注册到工厂
        MsgHandlerFactory.register(getMsgTypeEnum().getType(), this);
    }

    /**
     * 消息类型（子类实现）
     */
    abstract MessageTypeEnum getMsgTypeEnum();

    /**
     * 校验消息（钩子方法，子类可选实现）
     */
    protected void checkMsg(Req body, Long roomId, Long uid) {
        // 默认不校验，子类可重写
    }

    /**
     * 模板方法：统一处理流程
     */
    @Transactional
    public Long checkAndSaveMsg(ChatMessageReq request, Long uid) {
        // 1. 类型转换
        Req body = this.toBean(request.getBody());
        
        // 2. 统一校验
        AssertUtil.allCheckValidateThrow(body);
        
        // 3. 子类扩展校验
        checkMsg(body, request.getRoomId(), uid);
        
        // 4. 构建Message对象
        Message insert = MessageAdapter.buildMsgSave(request, uid);
        
        // 5. 统一保存（保存基础字段）
        messageDao.save(insert);
        
        // 6. 子类扩展保存（保存特有字段）
        saveMsg(insert, body);
        
        return insert.getId();
    }

    /**
     * 保存消息扩展字段（抽象方法，子类必须实现）
     */
    protected abstract void saveMsg(Message message, Req body);

    /**
     * 展示消息（抽象方法）
     */
    public abstract Object showMsg(Message msg);

    /**
     * 被回复时展示的消息
     */
    public abstract Object showReplyMsg(Message msg);

    /**
     * 会话列表展示的消息
     */
    public abstract String showContactMsg(Message msg);
}
```

**设计精妙之处：**
1. **泛型<Req>**：每个Handler处理不同的请求体类型
2. **反射获取泛型类型**：自动识别Req的具体类型，无需手动配置
3. **@PostConstruct自动注册**：Spring容器启动时自动注册到工厂
4. **模板方法**：`checkAndSaveMsg()`定义流程，子类填充具体逻辑
5. **钩子方法**：`checkMsg()`可选实现，灵活扩展

**具体策略示例1：文本消息处理器**

```java
@Component
public class TextMsgHandler extends AbstractMsgHandler<TextMsgReq> {
    @Autowired
    private MessageDao messageDao;
    @Autowired
    private SensitiveWordBs sensitiveWordBs;  // 敏感词过滤
    @Autowired
    private IRoleService iRoleService;
    
    private static final PrioritizedUrlDiscover URL_TITLE_DISCOVER = 
        new PrioritizedUrlDiscover();

    @Override
    MessageTypeEnum getMsgTypeEnum() {
        return MessageTypeEnum.TEXT;  // 标识类型
    }

    /**
     * 扩展校验：@用户、回复消息
     */
    @Override
    protected void checkMsg(TextMsgReq body, Long roomId, Long uid) {
        // 1. 校验回复消息是否存在
        if (Objects.nonNull(body.getReplyMsgId())) {
            Message replyMsg = messageDao.getById(body.getReplyMsgId());
            AssertUtil.isNotEmpty(replyMsg, "回复消息不存在");
            AssertUtil.equal(replyMsg.getRoomId(), roomId, "只能回复相同会话内的消息");
        }
        
        // 2. 校验@用户列表
        if (CollectionUtil.isNotEmpty(body.getAtUidList())) {
            List<Long> atUidList = body.getAtUidList().stream()
                .distinct()
                .collect(Collectors.toList());
            Map<Long, User> batch = userInfoCache.getBatch(atUidList);
            long batchCount = batch.values().stream()
                .filter(Objects::nonNull)
                .count();
            AssertUtil.equal((long)atUidList.size(), batchCount, "@用户不存在");
            
            // 3. 校验@全体成员权限
            boolean atAll = body.getAtUidList().contains(0L);
            if (atAll) {
                AssertUtil.isTrue(
                    iRoleService.hasPower(uid, RoleEnum.CHAT_MANAGER), 
                    "没有权限@全体成员"
                );
            }
        }
    }

    /**
     * 保存文本消息特有字段
     */
    @Override
    public void saveMsg(Message msg, TextMsgReq body) {
        MessageExtra extra = Optional.ofNullable(msg.getExtra())
            .orElse(new MessageExtra());
        Message update = new Message();
        update.setId(msg.getId());
        
        // 1. 敏感词过滤
        update.setContent(sensitiveWordBs.filter(body.getContent()));
        update.setExtra(extra);
        
        // 2. 保存回复消息信息
        if (Objects.nonNull(body.getReplyMsgId())) {
            Integer gapCount = messageDao.getGapCount(
                msg.getRoomId(), body.getReplyMsgId(), msg.getId()
            );
            update.setGapCount(gapCount);
            update.setReplyMsgId(body.getReplyMsgId());
        }
        
        // 3. URL识别和卡片生成
        Map<String, UrlInfo> urlContentMap = 
            URL_TITLE_DISCOVER.getUrlContentMap(body.getContent());
        extra.setUrlContentMap(urlContentMap);
        
        // 4. @用户列表
        if (CollectionUtil.isNotEmpty(body.getAtUidList())) {
            extra.setAtUidList(body.getAtUidList());
        }
        
        // 5. 更新数据库
        messageDao.updateById(update);
    }

    /**
     * 展示文本消息
     */
    @Override
    public Object showMsg(Message msg) {
        TextMsgResp resp = new TextMsgResp();
        resp.setContent(msg.getContent());
        resp.setUrlContentMap(
            Optional.ofNullable(msg.getExtra())
                .map(MessageExtra::getUrlContentMap)
                .orElse(null)
        );
        resp.setAtUidList(
            Optional.ofNullable(msg.getExtra())
                .map(MessageExtra::getAtUidList)
                .orElse(null)
        );
        
        // 处理回复消息展示
        Optional<Message> reply = Optional.ofNullable(msg.getReplyMsgId())
            .map(msgCache::getMsg)
            .filter(a -> Objects.equals(a.getStatus(), MessageStatusEnum.NORMAL.getStatus()));
        
        if (reply.isPresent()) {
            Message replyMessage = reply.get();
            TextMsgResp.ReplyMsg replyMsgVO = new TextMsgResp.ReplyMsg();
            replyMsgVO.setId(replyMessage.getId());
            replyMsgVO.setUid(replyMessage.getFromUid());
            replyMsgVO.setType(replyMessage.getType());
            
            // 递归获取回复消息的展示内容
            replyMsgVO.setBody(
                MsgHandlerFactory.getStrategyNoNull(replyMessage.getType())
                    .showReplyMsg(replyMessage)
            );
            
            User replyUser = userCache.getUserInfo(replyMessage.getFromUid());
            replyMsgVO.setUsername(replyUser.getName());
            replyMsgVO.setCanCallback(
                YesOrNoEnum.toStatus(
                    Objects.nonNull(msg.getGapCount()) && 
                    msg.getGapCount() <= MessageAdapter.CAN_CALLBACK_GAP_COUNT
                )
            );
            replyMsgVO.setGapCount(msg.getGapCount());
            resp.setReply(replyMsgVO);
        }
        
        return resp;
    }

    @Override
    public Object showReplyMsg(Message msg) {
        return msg.getContent();  // 回复时只展示文本内容
    }

    @Override
    public String showContactMsg(Message msg) {
        return msg.getContent();  // 会话列表展示文本内容
    }
}
```

**特色功能：**
- ✅ 敏感词过滤（DFA/AC自动机）
- ✅ URL自动识别和卡片生成
- ✅ @用户功能（含@全体成员权限校验）
- ✅ 消息回复（含跳转优化）

### 3.3 工厂模式（Factory Pattern）

#### **工厂类实现：**

```java
public class MsgHandlerFactory {
    // 存储所有Handler的映射
    private static final Map<Integer, AbstractMsgHandler> STRATEGY_MAP = new HashMap<>();

    /**
     * 注册Handler（由AbstractMsgHandler的@PostConstruct调用）
     */
    public static void register(Integer code, AbstractMsgHandler strategy) {
        STRATEGY_MAP.put(code, strategy);
    }

    /**
     * 获取Handler
     */
    public static AbstractMsgHandler getStrategyNoNull(Integer code) {
        AbstractMsgHandler strategy = STRATEGY_MAP.get(code);
        AssertUtil.isNotEmpty(strategy, CommonErrorEnum.PARAM_VALID);
        return strategy;
    }
}
```

**工厂的使用：**

```java
// 发送消息时
public Long sendMsg(ChatMessageReq request, Long uid) {
    // 1. 从工厂获取对应类型的Handler
    AbstractMsgHandler handler = MsgHandlerFactory.getStrategyNoNull(request.getMsgType());
    
    // 2. 调用Handler处理
    Long msgId = handler.checkAndSaveMsg(request, uid);
    
    // 3. 后续处理...
    return msgId;
}

// 展示消息时
public ChatMessageResp showMsg(Message msg) {
    // 根据消息类型获取Handler
    AbstractMsgHandler handler = MsgHandlerFactory.getStrategyNoNull(msg.getType());
    
    // 调用showMsg()获取展示内容
    Object body = handler.showMsg(msg);
    
    return ChatMessageResp.builder()
        .id(msg.getId())
        .type(msg.getType())
        .body(body)
        .build();
}
```

**设计优势：**
- ✅ 解耦：客户端不需要知道具体Handler的类名
- ✅ 扩展：新增Handler后自动注册，无需修改工厂
- ✅ 类型安全：使用Integer type作为key，避免字符串错误

### 3.4 模板方法模式（Template Method Pattern）

#### **模式定义：**
> 定义一个操作中算法的骨架，而将一些步骤延迟到子类中。模板方法使得子类可以不改变一个算法的结构即可重定义该算法的某些特定步骤。

#### **模板方法流程：**

```java
@Transactional
public Long checkAndSaveMsg(ChatMessageReq request, Long uid) {
    // ┌─────────────────────────────────────┐
    // │  第1步：类型转换（通用逻辑）        │
    // └─────────────────────────────────────┘
    Req body = this.toBean(request.getBody());
    
    // ┌─────────────────────────────────────┐
    // │  第2步：统一校验（通用逻辑）        │
    // └─────────────────────────────────────┘
    AssertUtil.allCheckValidateThrow(body);
    
    // ┌─────────────────────────────────────┐
    // │  第3步：子类扩展校验（钩子方法）     │
    // │  TextMsgHandler：校验@用户、回复    │
    // │  ImgMsgHandler：无额外校验          │
    // └─────────────────────────────────────┘
    checkMsg(body, request.getRoomId(), uid);
    
    // ┌─────────────────────────────────────┐
    // │  第4步：构建Message对象（通用逻辑）  │
    // └─────────────────────────────────────┘
    Message insert = MessageAdapter.buildMsgSave(request, uid);
    
    // ┌─────────────────────────────────────┐
    // │  第5步：保存基础字段（通用逻辑）     │
    // └─────────────────────────────────────┘
    messageDao.save(insert);
    
    // ┌─────────────────────────────────────┐
    // │  第6步：保存扩展字段（抽象方法）     │
    // │  TextMsgHandler：敏感词过滤、URL识别│
    // │  ImgMsgHandler：保存图片属性        │
    // └─────────────────────────────────────┘
    saveMsg(insert, body);
    
    return insert.getId();
}
```
