## 🎯 背景问题

### 业务场景
在 MallChat 聊天系统中，会话列表页面需要同时展示多个房间信息：

```java
// 场景1：会话列表（10个房间）
需要查询：
  - 10个房间基础信息
  - 10个房间的群组/好友信息
  - 10条最后消息
  - 10个发送者的用户信息
  - 10个房间的未读数

// 场景2：群成员列表（500人群）
需要查询：
  - 500个用户的基本信息（头像、昵称等）
```

### ❌ 传统方案的问题

#### 方案1：循环单次查询
```java
// 获取10个用户信息
List<Long> uids = Arrays.asList(1L, 2L, 3L, ..., 10L);
List<User> users = new ArrayList<>();

for (Long uid : uids) {
    // 问题：每次都查询一次Redis/数据库
    String key = "user:info:" + uid;
    User user = redisTemplate.opsForValue().get(key);
    if (user == null) {
        user = userDao.getById(uid);  // 数据库查询
        redisTemplate.opsForValue().set(key, user, 5, TimeUnit.MINUTES);
    }
    users.add(user);
}
```

**性能问题**：
- Redis查询：10次网络IO（假设每次5ms）→ **50ms**
- 数据库查询：10次查询 → **可能200ms+**
- **总耗时：250ms+**

#### 方案2：全部从数据库查
```java
// 直接批量查数据库
List<User> users = userDao.listByIds(uids);
```

**问题**：
- ❌ 没有利用缓存，数据库压力大
- ❌ QPS高时数据库容易打挂
- ❌ 响应时间长（数据库查询慢）

## 💡 设计原理

### 核心思想：**旁路缓存 + 批量查询**

```
┌─────────────────────────────────────────────────────┐
│           批量缓存框架执行流程                        │
└─────────────────────────────────────────────────────┘

输入：List<Long> uids = [1, 2, 3, 4, 5]

步骤1️⃣：组装Redis Key
  keys = ["user:info:1", "user:info:2", ..., "user:info:5"]

步骤2️⃣：批量查询Redis（1次网络IO）
  MGET user:info:1 user:info:2 user:info:3 user:info:4 user:info:5
  结果：[User1, null, User3, null, User5]  ← User2和User4缓存未命中

步骤3️⃣：计算差集（缓存未命中的ID）
  missIds = [2, 4]

步骤4️⃣：批量查询数据库（1次SQL）
  SELECT * FROM user WHERE id IN (2, 4)
  结果：[User2, User4]

步骤5️⃣：批量回写Redis（1次网络IO）
  MSET user:info:2 User2 user:info:4 User4

步骤6️⃣：合并结果
  最终返回：Map<Long, User> = {
    1 → User1,
    2 → User2,
    3 → User3,
    4 → User4,
    5 → User5
  }
```

### 性能提升
```
传统方案：5次Redis查询 + 2次数据库查询 = 7次网络IO
批量方案：1次MGET + 1次数据库 + 1次MSET = 3次网络IO

性能提升：60%+ 延迟降低
```

## 🏗️ 模板方法模式应用

### 设计模式结构

```
┌────────────────────────────────────────┐
│      BatchCache<IN, OUT>              │  ◀─ 顶层接口
│  ┌──────────────────────────────────┐ │
│  │ + get(IN)                        │ │
│  │ + getBatch(List<IN>)             │ │
│  │ + delete(IN)                     │ │
│  │ + deleteBatch(List<IN>)          │ │
│  └──────────────────────────────────┘ │
└────────────────────────────────────────┘
                    △
                    │ 实现
                    │
┌────────────────────────────────────────┐
│  AbstractRedisStringCache<IN, OUT>    │  ◀─ 抽象模板类
│  ┌──────────────────────────────────┐ │
│  │ 具体方法（已实现，不可变）         │ │
│  │ + getBatch(List<IN>)  ✅          │ │  ← 核心算法骨架
│  │ + deleteBatch(List<IN>) ✅        │ │
│  │                                  │ │
│  │ 抽象方法（子类必须实现）           │ │
│  │ # getKey(IN)           ❓         │ │  ← Hook方法
│  │ # getExpireSeconds()   ❓         │ │  ← Hook方法
│  │ # load(List<IN>)       ❓         │ │  ← Hook方法
│  └──────────────────────────────────┘ │
└────────────────────────────────────────┘
                    △
        ┌───────────┴──────────┬──────────────┐
        │                      │              │
┌───────────────┐    ┌─────────────────┐  ┌─────────────┐
│ UserInfoCache │    │  RoomCache      │  │ RoomGroup   │  ◀─ 具体实现类
│               │    │                 │  │   Cache     │
│ getKey()      │    │  getKey()       │  │             │
│ ↓ "user:1"    │    │  ↓ "room:1"     │  │  getKey()   │
│               │    │                 │  │  ↓"group:1" │
│ load()        │    │  load()         │  │             │
│ ↓ userDao     │    │  ↓ roomDao      │  │  load()     │
│               │    │                 │  │  ↓groupDao  │
└───────────────┘    └─────────────────┘  └─────────────┘
```

#### 1. **算法骨架统一，变化点可扩展**

## 🔧 代码实现详解

### 1️⃣ 顶层接口：BatchCache

```java
/**
 * 批量缓存顶层接口
 * @param <IN>  输入类型（通常是ID，如 Long）
 * @param <OUT> 输出类型（通常是实体，如 User）
 */
public interface BatchCache<IN, OUT> {
    /**
     * 获取单个（实际调用批量方法）
     */
    OUT get(IN req);
    
    /**
     * 批量获取（核心方法）
     */
    Map<IN, OUT> getBatch(List<IN> req);
    
    /**
     * 删除单个缓存
     */
    void delete(IN req);
    
    /**
     * 批量删除缓存
     */
    void deleteBatch(List<IN> req);
}
```

### 2️⃣ 抽象模板类：AbstractRedisStringCache

```java
/**
 * Redis String类型的批量缓存抽象类
 * 使用旁路缓存模式（Cache-Aside Pattern）
 */
public abstract class AbstractRedisStringCache<IN, OUT> 
    implements BatchCache<IN, OUT> {
    
    /**
     * 返回值类型（通过泛型反射获取）
     */
    private Class<OUT> outClass;
    
    /**
     * 构造方法：获取泛型实际类型
     */
    protected AbstractRedisStringCache() {
        ParameterizedType genericSuperclass = 
            (ParameterizedType) this.getClass().getGenericSuperclass();
        this.outClass = (Class<OUT>) genericSuperclass.getActualTypeArguments()[1];
    }
    
    // ========== 抽象方法（子类必须实现）==========
    
    /**
     * 生成Redis Key
     * @param req 请求参数（如用户ID）
     * @return Redis Key（如 "user:info:1"）
     */
    protected abstract String getKey(IN req);
    
    /**
     * 获取缓存过期时间
     * @return 秒数
     */
    protected abstract Long getExpireSeconds();
    
    /**
     * 从数据源加载数据（数据库、远程API等）
     * @param req 缓存未命中的请求列表
     * @return 加载的数据
     */
    protected abstract Map<IN, OUT> load(List<IN> req);
    
    // ========== 具体方法（模板算法骨架）==========
    
    /**
     * 单个获取（委托给批量方法）
     */
    @Override
    public OUT get(IN req) {
        return getBatch(Collections.singletonList(req)).get(req);
    }
    
    /**
     * 批量获取（核心算法）
     */
    @Override
    public Map<IN, OUT> getBatch(List<IN> req) {
        // 防御性编程：空列表直接返回
        if (CollectionUtil.isEmpty(req)) {
            return new HashMap<>();
        }
        
        // 1️⃣ 去重（避免重复查询）
        req = req.stream().distinct().collect(Collectors.toList());
        
        // 2️⃣ 组装Redis Key
        List<String> keys = req.stream()
            .map(this::getKey)  // 调用子类实现的getKey()
            .collect(Collectors.toList());
        
        // 3️⃣ 批量查询Redis（1次网络IO）
        List<OUT> valueList = RedisUtils.mget(keys, outClass);
        
        // 4️⃣ 差集计算（找出缓存未命中的）
        List<IN> loadReqs = new ArrayList<>();
        for (int i = 0; i < valueList.size(); i++) {
            if (Objects.isNull(valueList.get(i))) {
                loadReqs.add(req.get(i));  // 缓存未命中
            }
        }
        
        // 5️⃣ 批量加载数据库
        Map<IN, OUT> loadMap = new HashMap<>();
        if (CollectionUtil.isNotEmpty(loadReqs)) {
            // 调用子类实现的load()
            loadMap = load(loadReqs);
            
            // 6️⃣ 批量写入Redis（1次网络IO）
            Map<String, OUT> redisMap = loadMap.entrySet().stream()
                .map(entry -> Pair.of(getKey(entry.getKey()), entry.getValue()))
                .collect(Collectors.toMap(Pair::getFirst, Pair::getSecond));
            RedisUtils.mset(redisMap, getExpireSeconds());
        }
        
        // 7️⃣ 合并结果（缓存 + 数据库）
        Map<IN, OUT> resultMap = new HashMap<>();
        for (int i = 0; i < req.size(); i++) {
            IN in = req.get(i);
            OUT out = Optional.ofNullable(valueList.get(i))  // 优先从缓存取
                    .orElse(loadMap.get(in));                // 缓存没有从数据库取
            resultMap.put(in, out);
        }
        
        return resultMap;
    }
    
    /**
     * 删除缓存
     */
    @Override
    public void delete(IN req) {
        deleteBatch(Collections.singletonList(req));
    }
    
    @Override
    public void deleteBatch(List<IN> req) {
        List<String> keys = req.stream()
            .map(this::getKey)
            .collect(Collectors.toList());
        RedisUtils.del(keys);
    }
}
```

```java
        return 5 * 60L;

     * 从数据库批量加载用户信息

        // 转换为Map
        return needLoadUserList.stream()
            .collect(Collectors.toMap(User::getId, Function.identity()));
    }
}
```

```java
        // 1. 🚀 批量查询用户基本信息（复用UserInfoCache）
        Map<Long, User> userMap = userInfoCache.getBatch(uidList);
        
        // 2. 查询用户徽章信息
        List<ItemConfig> itemConfigs = itemCache.getByType(ItemTypeEnum.BADGE.getType());
        List<Long> itemIds = itemConfigs.stream()
            .map(ItemConfig::getId)
            .collect(Collectors.toList());
        List<UserBackpack> backpacks = userBackpackDao.getByItemIds(uidList, itemIds);
        Map<Long, List<UserBackpack>> userBadgeMap = backpacks.stream()
            .collect(Collectors.groupingBy(UserBackpack::getUid));
        
        // 3. 组装综合信息
        return uidList.stream().map(uid -> {
            SummeryInfoDTO dto = new SummeryInfoDTO();
            User user = userMap.get(uid);
            if (Objects.isNull(user)) {
                return null;
            }
            List<UserBackpack> userBackpacks = userBadgeMap.getOrDefault(uid, new ArrayList<>());
            dto.setUid(user.getId());
            dto.setName(user.getName());
            dto.setAvatar(user.getAvatar());
            dto.setLocPlace(Optional.ofNullable(user.getIpInfo())
                .map(IpInfo::getUpdateIpDetail)
                .map(IpDetail::getCity)
                .orElse(null));
            dto.setWearingItemId(user.getItemId());
            dto.setItemIds(userBackpacks.stream()
                .map(UserBackpack::getItemId)
                .collect(Collectors.toList()));
            return dto;
        })
        .filter(Objects::nonNull)
        .collect(Collectors.toMap(SummeryInfoDTO::getUid, Function.identity()));
    }
}
```

**🎯 设计亮点**：
- ✅ **缓存复用**：UserSummaryCache 内部调用 UserInfoCache.getBatch()
- ✅ **分层缓存**：基础信息缓存5分钟，综合信息缓存10分钟
- ✅ **按需加载**：只有需要徽章信息时才查询UserSummaryCache

```java
        .collect(Collectors.toList());
}
```

```java
            connection.setEx(
                k.getBytes(),
                time,
                JsonUtils.toStr(v).getBytes()
            );
        });
        return null;
    });
}
```

## 🛠️ 扩展示例：二级缓存

```java
/**
 * 支持本地缓存的批量缓存框架（二级缓存）
 */
public abstract class AbstractL2Cache<IN, OUT> 
    extends AbstractRedisStringCache<IN, OUT> {
    
    /**
     * Caffeine本地缓存
     */
    private Cache<IN, OUT> localCache = Caffeine.newBuilder()
        .maximumSize(1000)
        .expireAfterWrite(1, TimeUnit.MINUTES)
        .build();
    
    @Override
    public Map<IN, OUT> getBatch(List<IN> req) {
        // 1. 先查本地缓存
        Map<IN, OUT> result = new HashMap<>();
        List<IN> missLocal = new ArrayList<>();
        
        for (IN key : req) {
            OUT value = localCache.getIfPresent(key);
            if (value != null) {
                result.put(key, value);
            } else {
                missLocal.add(key);
            }
        }
        
        // 2. 本地缓存未命中，查Redis
        if (!missLocal.isEmpty()) {
            Map<IN, OUT> redisResult = super.getBatch(missLocal);
            result.putAll(redisResult);
            
            // 3. 回写本地缓存
            redisResult.forEach(localCache::put);
        }
        
        return result;
    }
}
```

```
    │   └─ outClass: Class<OUT>  (通过泛型反射获取)
    │
    ├─ 抽象方法（子类实现）
    │   ├─ getKey(IN): String
    │   ├─ getExpireSeconds(): Long
    │   └─ load(List<IN>): Map<IN, OUT>
    │
    └─ 具体方法（模板算法）
        ├─ get(IN): OUT
        ├─ getBatch(List<IN>): Map<IN, OUT>  ← 核心
        ├─ delete(IN)
        └─ deleteBatch(List<IN>)
    
    ↑ (继承)
    │
    ├─ UserInfoCache          → user:info:{uid}
    ├─ UserSummaryCache       → user:summary:{uid}
    ├─ RoomCache              → room:info:{roomId}
    ├─ RoomGroupCache         → group:info:{roomId}
    └─ RoomFriendCache        → room:friend:{roomId}
```

## 🎯 最佳实践建议

### ✅ DO（推荐做法）

1. **优先使用批量方法**
```java
// ✅ 推荐
List<Long> uids = Arrays.asList(1L, 2L, 3L);
Map<Long, User> userMap = userInfoCache.getBatch(uids);

// ❌ 不推荐
List<User> users = uids.stream()
    .map(userInfoCache::get)  // 内部还是调用getBatch，但创建了多个单元素列表
    .collect(Collectors.toList());
```

2. **提前收集ID再批量查询**
```java
// ✅ 推荐：先收集所有ID，一次查询
List<Long> allUids = messages.stream()
    .map(Message::getFromUid)
    .collect(Collectors.toList());
Map<Long, User> userMap = userInfoCache.getBatch(allUids);

// ❌ 不推荐：循环中查询
for (Message msg : messages) {
    User user = userInfoCache.get(msg.getFromUid());  // N次查询
}
```

3. **合理设置过期时间**
```java
// 基础信息：5分钟（变化少）
protected Long getExpireSeconds() {
    return 5 * 60L;
}

// 动态信息：1分钟（变化多）
protected Long getExpireSeconds() {
    return 60L;
}

// 加随机值避免缓存雪崩
protected Long getExpireSeconds() {
    return 5 * 60 + ThreadLocalRandom.current().nextInt(60);
}
```

### ❌ DON'T（避免做法）

1. **不要在循环中调用get()**
```java
// ❌ 性能差：N次查询
for (Long uid : uidList) {
    User user = userInfoCache.get(uid);
    // ...
}

// ✅ 优化：1次批量查询
Map<Long, User> userMap = userInfoCache.getBatch(uidList);
for (Long uid : uidList) {
    User user = userMap.get(uid);
    // ...
}
```

2. **不要忘记处理null值**
```java
// ❌ 可能NullPointerException
Map<Long, User> userMap = userInfoCache.getBatch(uidList);
for (Long uid : uidList) {
    String name = userMap.get(uid).getName();  // 💥 可能null
}

// ✅ 安全处理
for (Long uid : uidList) {
    User user = userMap.get(uid);
    if (user != null) {
        String name = user.getName();
    }
}
```

3. **不要缓存过大的对象**
```java
// ❌ 缓存包含大量数据的对象
protected Map<Long, UserWithAllInfo> load(List<Long> uids) {
    // UserWithAllInfo包含：消息列表、好友列表、订单列表...
    // 单个对象可能上百KB
}

// ✅ 只缓存必要字段
protected Map<Long, User> load(List<Long> uids) {
    // User只包含：id、name、avatar等基础字段
    // 单个对象几KB
}
```

### 如何在面试中展示这个项目？

**场景还原**：
> "在MallChat项目中，我发现会话列表接口响应时间达到380ms，经过分析，发现是因为循环查询Redis导致大量网络IO。
> 
> 我设计并实现了一个基于**模板方法模式**的批量缓存框架，核心思路是：
> 1. 使用Redis的MGET/MSET命令，将多次查询合并为1次
> 2. 抽象类实现固定的算法骨架，子类实现变化点（Hook方法）
> 3. 支持自动降级，Redis宕机时仍可查数据库
> 
> 优化后，接口响应时间降低到45ms，**性能提升8.4倍**，数据库QPS降低90%。
> 
> 这个框架在项目中被广泛使用，有5个缓存类继承了它，代码复用率达到90%。"
