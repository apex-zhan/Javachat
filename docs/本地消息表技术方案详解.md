## 一、STAR原则项目描述

### 🎯 **S - Situation（背景与挑战）**

**业务背景：**
在MallChat即时通讯系统中，需要保证：
- **消息持久化 + MQ发送**：先保存消息到DB，再发送到MQ
- **用户注册 + 发送欢迎邮件**：先注册用户，再调用邮件服务
- **订单创建 + 扣减库存**：先创建订单，再调用库存服务

**核心挑战：**

| 挑战 | 具体场景 | 后果 |
|-----|---------|------|
| **分布式一致性** | DB事务提交了，但MQ发送失败 | 数据不一致 |
| **网络不可靠** | 调用第三方服务超时/失败 | 操作丢失 |
| **事务边界** | 本地事务无法控制远程调用 | 无法回滚 |
| **重试困难** | 失败后无法自动重试 | 需要人工介入 |

**典型问题场景：**

```java
@Transactional
public void sendMessage(Long roomId, String content) {
    // 1. 保存消息到DB（本地事务）
    Message message = messageDao.save(new Message(...));
    
    // 2. 发送MQ（第三方操作）
    mqProducer.send("topic", message);  // ❌ 可能失败，且无法回滚DB
}
```

**问题分析：**
- 事务只能保证DB操作的原子性
- MQ发送失败，DB已提交 → **数据不一致**
- 网络波动、MQ宕机 → **消息丢失**

---

### 🎯 **T - Target（设计目标）**

基于上述挑战，设计目标拆解为：

#### **目标1：保证最终一致性**
- DB操作和MQ发送要么都成功，要么都失败
- 允许短暂不一致，但最终必须一致
- 失败后自动重试，直到成功

#### **目标2：高度抽象，通用化**
- 不仅适用于MQ，还适用于Dubbo、HTTP等所有第三方调用
- 框架级别支持，业务代码零侵入
- 只需加注解即可使用

#### **目标3：可靠的重试机制**
- 失败后自动重试
- 指数退避策略（2分钟、4分钟、8分钟...）
- 超过最大重试次数后标记为失败，支持人工介入

#### **目标4：性能与可扩展性**
- 异步执行，不阻塞主线程
- 支持同步/异步两种模式
- 定时任务批量处理，避免频繁扫描

## 二、分布式事务背景

### 2.1 分布式一致性问题

**单体应用（简单）：**

```java
@Transactional
public void createOrder(Order order) {
    // 1. 创建订单
    orderDao.save(order);
    
    // 2. 扣减库存
    stockDao.reduceStock(order.getProductId(), order.getCount());
    
    // 3. 更新用户积分
    userDao.updatePoints(order.getUserId(), order.getPoints());
}
// 同一个数据库，事务可以保证原子性
```

**微服务架构（复杂）：**

```java
@Transactional
public void createOrder(Order order) {
    // 1. 创建订单（本地DB）
    orderDao.save(order);
    
    // 2. 扣减库存（远程调用库存服务）
    stockService.reduceStock(order.getProductId(), order.getCount());  // ❌
    
    // 3. 更新积分（远程调用用户服务）
    userService.updatePoints(order.getUserId(), order.getPoints());  // ❌
}
// 问题：本地事务无法控制远程调用
```

**问题场景：**

```
情况1：订单创建成功 → 库存扣减失败 → ❌ 订单无库存
情况2：订单创建成功 → 库存扣减成功 → 积分更新失败 → ❌ 数据不一致
情况3：订单创建成功 → 网络超时 → 不知道是否成功 → ❌ 不确定状态
```

---

### 2.2 常见分布式事务方案

| 方案             | 原理                 | 优点     | 缺点       | 适用场景      |
| -------------- | ------------------ | ------ | -------- | --------- |
| **2PC（两阶段提交）** | 协调者+参与者，准备+提交      | 强一致性   | 同步阻塞，性能差 | 金融、支付     |
| **3PC（三阶段提交）** | 增加超时机制             | 减少阻塞   | 实现复杂     | 对一致性要求高   |
| **TCC**        | Try-Confirm-Cancel | 灵活，性能好 | 业务侵入大    | 订单、库存     |
| **本地消息表** ✅    | 持久化+重试             | 简单，性能好 | 最终一致性    | **大部分场景** |
| **MQ事务消息**     | RocketMQ事务         | 简单     | 依赖MQ     | 异步场景      |

| 方案     | 一致性类型 | 性能  | 实现复杂度 | 业务侵入    | 适用场景   |
| ------ | ----- | --- | ----- | ------- | ------ |
| 2PC    | 强一致   | 低   | 中     | 无（数据库层） | 金融、支付  |
| 3PC    | 强一致   | 中低  | 高     | 无       | 高一致性要求 |
| TCC    | 最终一致  | 高   | 高     | 强       | 订单、库存  |
| 本地消息表  | 最终一致  | 高   | 低     | 中       | 通用业务   |
| MQ事务消息 | 最终一致  | 高   | 低     | 弱（依赖MQ） | 异步场景   |


**为什么选择本地消息表？**

✅ **实现简单**：只需一张表 + 定时任务  
✅ **通用性强**：适用于所有第三方调用  
✅ **性能好**：异步执行，不阻塞主流程  
✅ **可靠性高**：持久化 + 重试保证最终成功

## 三、本地消息表核心原理

### 3.1 核心思想

**关键点：把对第三方的操作，转换为对本地方法执行的保证**

```
问题：如何保证 DB操作 + MQ发送 一致？

传统方案：
1. DB操作（本地事务）✅
2. MQ发送（第三方）❌ 可能失败

本地消息表方案：
1. DB操作（本地事务）✅
2. 保存"执行MQ发送"的记录到DB（本地事务）✅ 
3. 定时任务读取记录，执行MQ发送 ✅ 失败重试
```

**核心流程：**

```
┌──────────────────────────────────────────────┐
│              本地消息表核心流程               │
└──────────────────────────────────────────────┘

1. 业务方法（带@SecureInvoke注解）
   ↓
┌─────────────────────────────────────┐
│  @Transactional                      │
│  public void sendMessage() {         │
│      // 1. 保存消息到DB               │
│      messageDao.save(message);       │
│                                      │
│      // 2. 发送MQ（带@SecureInvoke） │
│      mqProducer.sendSecureMsg(...);  │
│  }                                   │
└─────────────────────────────────────┘
   ↓
2. AOP切面拦截@SecureInvoke
   ↓
┌─────────────────────────────────────┐
│  - 序列化方法调用信息                │
│  - 保存到secure_invoke_record表      │
│  - 注册事务同步器                    │
└─────────────────────────────────────┘
   ↓
3. 事务提交
   ↓
┌─────────────────────────────────────┐
│  - message表数据已提交               │
│  - secure_invoke_record表已提交      │
│  （持久化完成，不会丢失）             │
└─────────────────────────────────────┘
   ↓
4. 事务提交后（TransactionSynchronization）
   ↓
┌─────────────────────────────────────┐
│  - 异步执行MQ发送                    │
│  - 成功：删除记录                    │
│  - 失败：等待定时任务重试            │
└─────────────────────────────────────┘
   ↓
5. 定时任务（每5秒）
   ↓
┌─────────────────────────────────────┐
│  - 扫描待重试的记录                  │
│  - 反射调用方法                      │
│  - 指数退避重试（2m、4m、8m...）     │
│  - 超过最大次数标记为失败            │
└─────────────────────────────────────┘
```

### 3.2 数据库表设计

```sql
CREATE TABLE `secure_invoke_record` (
  `id` bigint unsigned NOT NULL AUTO_INCREMENT,
  `secure_invoke_json` json NOT NULL COMMENT '请求快照参数json',
  `status` tinyint NOT NULL DEFAULT 1 COMMENT '状态 1待执行 2已失败',
  `next_retry_time` datetime(3) NOT NULL COMMENT '下一次重试的时间',
  `retry_times` int NOT NULL DEFAULT 0 COMMENT '已经重试的次数',
  `max_retry_times` int NOT NULL COMMENT '最大重试次数',
  `fail_reason` text COMMENT '执行失败的堆栈',
  `create_time` datetime(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  `update_time` datetime(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  PRIMARY KEY (`id`),
  KEY `idx_next_retry_time` (`next_retry_time`)  -- ✅ 重要：定时任务查询索引
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='本地消息表';
```

**字段说明：**

| 字段 | 类型 | 说明 | 设计要点 |
|-----|------|------|---------|
| `secure_invoke_json` | JSON | 方法调用快照 | 存储类名、方法名、参数类型、参数值 |
| `status` | TINYINT | 状态 | 1=待执行，2=已失败 |
| `next_retry_time` | DATETIME(3) | 下次重试时间 | **索引**，定时任务按此字段查询 |
| `retry_times` | INT | 已重试次数 | 用于判断是否超过最大次数 |
| `max_retry_times` | INT | 最大重试次数 | 注解配置，默认3次 |
| `fail_reason` | TEXT | 失败原因 | 记录异常堆栈，便于排查 |

### 3.3 方法调用的高度抽象

**为什么能支持所有第三方调用？**

**关键洞察：所有操作本质都是调用Java方法**

```java
// MQ发送
mqProducer.send("topic", message);
→ 类：MQProducer，方法：send，参数：["topic", message]

// Dubbo调用
stockService.reduceStock(productId, count);
→ 类：StockService，方法：reduceStock，参数：[productId, count]

// HTTP调用
httpClient.post(url, body);
→ 类：HttpClient，方法：post，参数：[url, body]
```

**统一抽象：**

```
任何第三方调用 = 执行某个类的某个方法
                ↓
          本地消息表只需存储：
          1. 类名（className）
          2. 方法名（methodName）
          3. 参数类型（parameterTypes）
          4. 参数值（args）
                ↓
          定时任务通过反射调用：
          Class.forName(className)
            .getMethod(methodName, parameterTypes)
            .invoke(bean, args)
```

### 4.2 核心组件

#### **组件1：@SecureInvoke注解**

```java
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface SecureInvoke {
    
    /**
     * 最大重试次数（包括第一次执行）
     */
    int maxRetryTimes() default 3;
    
    /**
     * 是否异步执行
     * - true：异步，不阻塞主线程（默认），使用线程池
     * - false：同步，适合MQ消费场景
     */
    boolean async() default true;
}
```

**使用示例：**

```java
// 异步执行，最多重试5次
@SecureInvoke(maxRetryTimes = 5, async = true)
public void sendSecureMsg(String topic, Object body) {
    rocketMQTemplate.send(topic, message);
}
```

#### **组件2：SecureInvokeAspect切面**

```java
@Aspect
@Order(Ordered.HIGHEST_PRECEDENCE + 1)  // 确保最先执行
@Component
public class SecureInvokeAspect {
    
    @Autowired
    private SecureInvokeService secureInvokeService;
    
    @Around("@annotation(secureInvoke)")
    public Object around(ProceedingJoinPoint joinPoint, SecureInvoke secureInvoke) {
        boolean async = secureInvoke.async();
        boolean inTransaction = TransactionSynchronizationManager.isActualTransactionActive();
        
        // 1. 非事务状态，直接执行
        if (!inTransaction) {
            return joinPoint.proceed();
        }
        
        // 2. 正在重试执行中，直接执行（避免递归）
        if (SecureInvokeHolder.isInvoking()) {
            return joinPoint.proceed();
        }
        
        // 3. 序列化方法调用信息
        Method method = ((MethodSignature) joinPoint.getSignature()).getMethod();
        List<String> parameters = Stream.of(method.getParameterTypes())
            .map(Class::getName)
            .collect(Collectors.toList());
        
        SecureInvokeDTO dto = SecureInvokeDTO.builder()
            .className(method.getDeclaringClass().getName())
            .methodName(method.getName())
            .parameterTypes(JsonUtils.toStr(parameters))
            .args(JsonUtils.toStr(joinPoint.getArgs()))
            .build();
        
        // 4. 构建记录
        SecureInvokeRecord record = SecureInvokeRecord.builder()
            .secureInvokeDTO(dto)
            .maxRetryTimes(secureInvoke.maxRetryTimes())
            .nextRetryTime(DateUtil.offsetMinute(new Date(), 2))  // 2分钟后重试
            .build();
        
        // 5. 保存记录 + 注册事务同步器
        secureInvokeService.invoke(record, async);
        
        return null;  // 异步执行，不返回结果
    }
}
```

**关键点：**
1. **事务检测**：`TransactionSynchronizationManager.isActualTransactionActive()`
2. **递归防护**：`SecureInvokeHolder.isInvoking()` 避免重试时再次拦截
3. **方法序列化**：保存类名、方法名、参数类型、参数值
4. **异步标记**：根据注解决定同步/异步执行

#### **组件3：SecureInvokeService核心服务**

```java
@AllArgsConstructor
public class SecureInvokeService {
    
    public static final double RETRY_INTERVAL_MINUTES = 2D;
    
    private final SecureInvokeRecordDao secureInvokeRecordDao;
    private final Executor executor;
    
    /**
     * 保存记录 + 注册事务同步器
     */
    public void invoke(SecureInvokeRecord record, boolean async) {
        // 1. 保存记录到DB（和业务数据同一事务）
        secureInvokeRecordDao.save(record);
        
        // 2. 注册事务同步器
        TransactionSynchronizationManager.registerSynchronization(
            new TransactionSynchronization() {
                @Override
                public void afterCommit() {
                    // 事务提交后执行
                    if (async) {
                        doAsyncInvoke(record);  // 异步
                    } else {
                        doInvoke(record);  // 同步
                    }
                }
            }
        );
    }
    
    /**
     * 异步执行
     */
    public void doAsyncInvoke(SecureInvokeRecord record) {
        executor.execute(() -> doInvoke(record));
    }
    
    /**
     * 执行方法调用（核心）
     */
    public void doInvoke(SecureInvokeRecord record) {
        SecureInvokeDTO dto = record.getSecureInvokeDTO();
        
        try {
            // 1. 标记正在执行（避免AOP再次拦截）
            SecureInvokeHolder.setInvoking();
            
            // 2. 反射获取类
            Class<?> beanClass = Class.forName(dto.getClassName());
            Object bean = SpringUtil.getBean(beanClass);
            
            // 3. 反射获取方法
            List<String> parameterStrings = JsonUtils.toList(dto.getParameterTypes(), String.class);
            List<Class<?>> parameterClasses = parameterStrings.stream()
                .map(name -> Class.forName(name))
                .collect(Collectors.toList());
            Method method = ReflectUtil.getMethod(
                beanClass, 
                dto.getMethodName(), 
                parameterClasses.toArray(new Class[]{})
            );
            
            // 4. 反序列化参数
            Object[] args = getArgs(dto, parameterClasses);
            
            // 5. 执行方法
            method.invoke(bean, args);
            
            // 6. 执行成功，删除记录
            secureInvokeRecordDao.removeById(record.getId());
            
        } catch (Throwable e) {
            log.error("SecureInvokeService invoke fail", e);
            // 7. 执行失败，更新重试信息
            retryRecord(record, e.getMessage());
        } finally {
            SecureInvokeHolder.invoked();
        }
    }
    
    /**
     * 定时任务：每5秒扫描待重试记录
     */
    @Scheduled(cron = "*/5 * * * * ?")
    public void retry() {
        List<SecureInvokeRecord> records = secureInvokeRecordDao.getWaitRetryRecords();
        for (SecureInvokeRecord record : records) {
            doAsyncInvoke(record);
        }
    }
    
    /**
     * 更新重试信息
     */
    private void retryRecord(SecureInvokeRecord record, String errorMsg) {
        Integer retryTimes = record.getRetryTimes() + 1;
        
        SecureInvokeRecord update = new SecureInvokeRecord();
        update.setId(record.getId());
        update.setFailReason(errorMsg);
        update.setNextRetryTime(getNextRetryTime(retryTimes));  // 指数退避
        
        if (retryTimes > record.getMaxRetryTimes()) {
            // 超过最大次数，标记为失败
            update.setStatus(SecureInvokeRecord.STATUS_FAIL);
        } else {
            update.setRetryTimes(retryTimes);
        }
        
        secureInvokeRecordDao.updateById(update);
    }
    
    /**
     * 指数退避重试策略
     * 2分钟 → 4分钟 → 8分钟 → 16分钟 → 32分钟...
     */
    private Date getNextRetryTime(Integer retryTimes) {
        double waitMinutes = Math.pow(RETRY_INTERVAL_MINUTES, retryTimes);
        return DateUtil.offsetMinute(new Date(), (int) waitMinutes);
    }
}
```

**关键技术点：**

1. **事务同步器**：`TransactionSynchronizationManager.registerSynchronization`
   - 事务提交后才执行，保证DB已持久化
   
2. **反射调用**：
   - `Class.forName(className)` 获取类
   - `SpringUtil.getBean(beanClass)` 从Spring容器获取Bean
   - `method.invoke(bean, args)` 执行方法
   
3. **指数退避**：`Math.pow(2, retryTimes)`
   - 第1次：2分钟后
   - 第2次：4分钟后
   - 第3次：8分钟后
   - ...

4. **递归防护**：`SecureInvokeHolder`
   ```java
   public class SecureInvokeHolder {
       private static final ThreadLocal<Boolean> INVOKE_THREAD_LOCAL = new ThreadLocal<>();
       
       public static boolean isInvoking() {
           return Objects.nonNull(INVOKE_THREAD_LOCAL.get());
       }
       
       public static void setInvoking() {
           INVOKE_THREAD_LOCAL.set(Boolean.TRUE);
       }
       
       public static void invoked() {
           INVOKE_THREAD_LOCAL.remove();
       }
   }
   ```

#### **组件4：数据实体**

```java
@Data
@Builder
@TableName(value = "secure_invoke_record", autoResultMap = true)
public class SecureInvokeRecord {
    public final static byte STATUS_WAIT = 1;
    public final static byte STATUS_FAIL = 2;
    
    @TableId(value = "id", type = IdType.AUTO)
```

```java
public abstract class AbstractSecureInvokeTemplate {

     * 模板方法：定义执行流程
     */
    public final void execute(SecureInvokeRecord record) {
        try {
            // 1. 前置校验
            if (!validate(record)) {
                return;
            }
            
            // 2. 执行方法（子类实现）
            doInvoke(record);
            
            // 3. 成功回调
            onSuccess(record);

            // 4. 失败回调
            onFailure(record, e);
        }
    }
    
    /**
     * 校验（钩子方法）

    protected boolean validate(SecureInvokeRecord record) {
        return record != null && record.getRetryTimes() <= record.getMaxRetryTimes();
    }
    
    /**
     * 执行方法（抽象方法，子类必须实现）

    protected abstract void doInvoke(SecureInvokeRecord record) throws Exception;
    
    /**
     * 成功回调（钩子方法）

    protected void onSuccess(SecureInvokeRecord record) {
        removeRecord(record.getId());

    /**
     * 失败回调（钩子方法）

    }
```

## 九、面试高频问题

### 9.1 为什么需要本地消息表？

**【STAR回答】**

**S - Situation：**
> "在MallChat项目中，发送消息需要保存到DB，同时发送MQ通知推送服务。但本地事务无法控制MQ发送，如果DB提交成功但MQ发送失败，就会导致消息保存了但用户收不到推送，数据不一致。"

**T - Target：**
> "设计目标是保证DB操作和MQ发送的最终一致性，要么都成功，要么都失败。允许短暂不一致，但最终必须一致。"

**A - Action：**
> "我设计了本地消息表框架：
> 1. **持久化**：把MQ发送操作记录到DB，和业务数据在同一事务
> 2. **事务同步器**：事务提交后异步执行MQ发送
> 3. **定时重试**：失败后定时任务自动重试，指数退避策略
> 4. **最终成功**：重试直到成功或超过最大次数"

**R - Result：**
> "最终实现：
> - ✅ 保证了最终一致性，消息必达率99.99%
> - ✅ 框架通用化，支持MQ、Dubbo、HTTP等所有第三方调用
> - ✅ 业务零侵入，只需加@SecureInvoke注解
> - ✅ 性能优异，异步执行不阻塞主线程"

```java
    } finally {

    }
}
```

### 9.5 如何避免重复拦截（递归调用）？

**【技术细节回答】**

**问题：**

```java
// 第1次调用：被AOP拦截，保存记录
@SecureInvoke
public void sendMQ(Long msgId) {
    mqProducer.send(topic, msgId);
}

// 定时任务重试：再次调用sendMQ
// 会再次被AOP拦截吗？ → 会导致无限循环！
```

**解决方案：ThreadLocal标记**

```java
public class SecureInvokeHolder {
    private static final ThreadLocal<Boolean> INVOKE_THREAD_LOCAL = new ThreadLocal<>();
    
    public static boolean isInvoking() {
        return Objects.nonNull(INVOKE_THREAD_LOCAL.get());
    }
    
    public static void setInvoking() {
        INVOKE_THREAD_LOCAL.set(Boolean.TRUE);
    }
    
    public static void invoked() {
        INVOKE_THREAD_LOCAL.remove();
    }
}

// AOP切面中检查
@Around("@annotation(secureInvoke)")
public Object around(ProceedingJoinPoint joinPoint) {
    // ✅ 正在重试执行中，直接放行
    if (SecureInvokeHolder.isInvoking()) {
        return joinPoint.proceed();
    }
    
    // 正常拦截...
}

// 重试时设置标记
public void doInvoke(SecureInvokeRecord record) {
    try {
        SecureInvokeHolder.setInvoking();  // ✅ 设置标记
        method.invoke(bean, args);
    } finally {
        SecureInvokeHolder.invoked();  // ✅ 清除标记
    }
}
```
