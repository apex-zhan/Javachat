## 📊 核心数据速查

### 性能提升数据

| 指标 | 优化前 | 优化后 | 提升幅度 |
|-----|--------|--------|---------|
| 消息副本（万人群） | 30000份 | 79KB | **↓ 99.7%** |
| 推送延迟（P99） | 5秒+ | 50ms | **↓ 99%** |
| 带宽成本 | 30MB | 790KB | **↓ 97.4%** |
| Redis QPS | 10万+ | 0 | **无需Redis** |

### 方案选择速查

```
用户规模 < 50人     → 精准推送（Redis查询 + 直接推送）
用户规模 ≥ 50人     → 集群广播（MQ广播 + 本地过滤）
用户规模 ≥ 1万人    → 集群广播（消息体共享）
用户规模 ≥ 100万人  → 热点隔离（专属集群 + 消息合并）
```

### 核心技术栈

- **WebSocket**：Netty
- **消息队列**：RocketMQ（BROADCASTING模式）
- **缓存**：Redis（用户位置）、Caffeine（本地缓存）
- **设计模式**：策略、观察者、模板方法、工厂
- **优化技术**：零拷贝、Pipeline批量查询、异步并发

## 🎨 架构速览

### 单机架构（起点）

```
用户 → WebSocket → 本地Map → 推送
```

**问题**：无法集群部署

---

### 精准投递架构（适合小群）

```
用户 → WebSocket集群
         ↓
      Redis（用户位置）
         ↓
      Router服务 → 精准推送
```

**优点**：单聊效率高  
**缺点**：大群扇出压力大

---

### 集群广播架构（适合大群）✅ 推荐

```
用户 → WebSocket集群
         ↑
      RocketMQ（广播）
         ↑
      IM业务层（只发1次）
```

**优点**：
- ✅ 消息副本少（节省99%）
- ✅ 无需Router
- ✅ 架构简单

**缺点**：
- ❌ 小群有浪费

---

### 混合架构（生产推荐）✅ 最优

```java
if (uids.size() < 50) {
    精准推送();  // 小群高效
} else {
    集群广播();  // 大群节省
}
```

## 🔍 问题索引

### Q1: 为什么集群广播比精准投递更优？

**答案位置**：第四章、第五章

**核心要点**：
- 万人群聊，精准投递需要10000次MQ发送
- 集群广播只需1次MQ发送 + 本地过滤
- 消息体共享，节省99%带宽

---

### Q2: RocketMQ的BROADCASTING模式如何工作？

**答案位置**：第八章 8.5节

**核心要点**：
```java
@RocketMQMessageListener(
    messageModel = MessageModel.BROADCASTING
)
```
- 每条消息被所有消费者接收
- 各节点本地过滤，只推送本地用户

---

### Q3: 如何保证消息时序性？

**答案位置**：第七章

**核心要点**：
- 使用数据库自增ID（全局唯一、严格递增）
- 查询时只按ID排序
- 避免用时间戳（毫秒内可能重复）

---

### Q4: 百万级直播如何推送？

**答案位置**：第六章

**核心要点**：
- 热点识别：人数 > 1万标记为热点
- K8s动态扩容专属WebSocket集群
- 消息合并：点赞、礼物批量推送
- 优先级隔离：重要消息独立Topic

---

### Q5: 有哪些设计模式应用？

**答案位置**：第十二章

**核心模式**：
1. **策略模式**：推送策略选择（精准/广播）
2. **观察者模式**：用户上下线事件通知
3. **模板方法模式**：推送流程统一
4. **工厂模式**：消息类型构建

### 核心知识点记录

**问题**：集群推送难题是什么？

**答案**：
- 连接分散在不同节点
- 不知道用户在哪台机器
- 万人群聊扇出压力大

---

**问题**：集群广播为什么更优？

**答案**：
1. MQ只发送1次（vs 精准投递10000次）
2. 消息体共享（节省99%带宽）
3. 无需Router服务（架构简化）

---

**问题**：核心优化点有哪些？

**答案**：
1. **架构**：混合推送策略
2. **消息**：消息体共享
3. **批量**：frame.retain()共享ByteBuf
4. **并发**：CompletableFuture异步推送
5. **网络**：Netty零拷贝、Redis Pipeline
