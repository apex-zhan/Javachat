## 一、STAR原则项目描述

### 🎯 **S - Situation（背景与挑战）**

**业务背景：**
在MallChat即时通讯系统中，需要支持：
- **单聊消息**：一对一精准推送
- **群聊消息**：一对多扇出推送
- **全员群聊**：万人群聊消息推送
- **集群部署**：WebSocket服务水平扩展（10+节点）

**核心挑战：**

| 挑战 | 具体问题 | 影响 |
|-----|---------|------|
| **连接分散** | WebSocket连接分散在不同节点 | 不知道用户在哪台机器 |
| **消息扇出** | 万人群聊需要扇出1万次 | 单点压力巨大，延迟叠加 |
| **消息副本** | 精准推送需要多份消息副本 | 网络IO浪费，带宽成本高 |
| **时序性** | 并发场景消息顺序错乱 | 用户体验差 |

---

### 🎯 **T - Target（设计目标）**

基于上述挑战，设计目标拆解为：

#### **目标1：解决集群推送问题**
- 用户连接可能在任意节点，如何推送到正确的用户？
- 无需额外的注册中心或Router服务
- 支持10+节点水平扩展

#### **目标2：优化消息扇出性能**
- 万人群聊：扇出次数从10000降至1次
- 消息副本：从10000份降至10份（节点数）
- 延迟：P99 < 100ms

#### **目标3：降低网络开销**
- 消息传输次数：精准推送 vs 集群广播对比
- 带宽成本：大群聊场景节省90%+

#### **目标4：保证消息时序性**
- 单聊：客户端序列号 + 服务端时间戳
- 群聊：服务端唯一ID保证全局有序

## 二、集群推送核心方案

### 2.1 问题分析

**单机场景（简单）：**
```java
// 本地维护连接
private static final Map<Long, Channel> ONLINE_MAP = new ConcurrentHashMap<>();

// 推送消息
public void sendMsg(Long uid, WSBaseResp msg) {
    Channel channel = ONLINE_MAP.get(uid);
    if (channel != null) {
        channel.writeAndFlush(new TextWebSocketFrame(JSONUtil.toJsonStr(msg)));
    }
}
```

**集群场景（复杂）：**

```
用户A连接 → WebSocket节点1
用户B连接 → WebSocket节点2
用户C连接 → WebSocket节点3

问题：A发消息给C，但A在节点1，C在节点3，如何推送？
```

**架构对比：**

```
┌─────────────────────────────────────────────┐
│              单机架构（简单）                │
├─────────────────────────────────────────────┤
│  用户 → WebSocket → 本地Map查Channel → 推送 │
└─────────────────────────────────────────────┘

┌─────────────────────────────────────────────┐
│              集群架构（复杂）                │
├─────────────────────────────────────────────┤
│  用户 → WebSocket节点1                       │
│      ↓                                       │
│  IM服务（负载均衡）                          │
│      ↓                                       │
│  如何推送给节点3的用户？ ❓                  │
└─────────────────────────────────────────────┘
```

---

### 2.2 方案对比

| 方案 | 核心思路 | 优点 | 缺点 | 适用场景 |
|-----|---------|------|------|---------|
| **精准投递** | Redis记录用户位置，Router精准路由 | 单聊效率高 | 连接数爆炸、扇出压力大 | 单聊为主 |
| **集群广播** | MQ广播所有节点，本地过滤 | 群聊效率高、无需Router | 小群/单聊浪费 | 群聊为主 |
| **混合方案** | 单聊精准+群聊广播 | 综合最优 | 实现复杂 | 生产推荐 |

## 三、精准投递方案详解

### 3.1 方案架构

```
┌──────────────────────────────────────────────────┐
│              精准投递架构                         │
└──────────────────────────────────────────────────┘

1. 用户连接时，记录位置
   ↓
┌─────────────────────────────────────┐
│  Redis存储映射关系                   │
│  uid → WebSocket节点IP               │
│  1001 → 10.102.1.1                  │
│  1002 → 10.102.1.2                  │
└─────────────────────────────────────┘

2. 发送消息
   ↓
┌─────────────────────────────────────┐
│  IM服务 → Router服务                 │
│  Router查Redis：用户C在节点2          │
│  Router → 节点2推送                   │
└─────────────────────────────────────┘

3. 推送到用户
   ↓
┌─────────────────────────────────────┐
│  节点2收到推送请求                    │
│  本地Map查Channel                     │
│  channel.write(消息)                  │
└─────────────────────────────────────┘
```

### 3.2 核心代码

#### **连接管理（本地维护）**

```java
@Component
public class WebSocketService {
    // 本地连接管理
    private static final Map<Long, Channel> ONLINE_MAP = new ConcurrentHashMap<>();
    
    // 用户连接时
    public void online(Long uid, Channel channel) {
        ONLINE_MAP.put(uid, channel);
        // 同时记录到Redis
        redisTemplate.opsForValue().set(
            "ws:uid:" + uid, 
            getLocalIp(), 
            30, 
            TimeUnit.MINUTES
        );
    }
    
    // 本地推送
    public void sendMsgLocal(Long uid, WSBaseResp msg) {
        Channel channel = ONLINE_MAP.get(uid);
        if (channel != null) {
            channel.writeAndFlush(new TextWebSocketFrame(JSONUtil.toJsonStr(msg)));
        }
    }
}
```

#### **Router服务（精准路由）**

```java
@Service
public class RouterService {
    @Autowired
    private RedisTemplate redisTemplate;
    
    // 精准推送
    public void sendMsg(Long uid, WSBaseResp msg) {
        // 1. 查询用户所在节点
        String nodeIp = redisTemplate.opsForValue().get("ws:uid:" + uid);
        
        if (nodeIp == null) {
            // 用户离线，发送离线推送
            pushService.sendOfflinePush(uid, msg);
            return;
        }
        
        // 2. 精准推送到目标节点
        if (nodeIp.equals(getLocalIp())) {
            // 本地推送
            webSocketService.sendMsgLocal(uid, msg);
        } else {
            // 远程推送（通过Dubbo/HTTP）
            webSocketRpc.sendMsg(nodeIp, uid, msg);
        }
    }
    
    // 群聊扇出
    public void sendGroupMsg(List<Long> uids, WSBaseResp msg) {
        // 按节点分组
        Map<String, List<Long>> nodeMap = new HashMap<>();
        for (Long uid : uids) {
            String nodeIp = redisTemplate.opsForValue().get("ws:uid:" + uid);
            if (nodeIp != null) {
                nodeMap.computeIfAbsent(nodeIp, k -> new ArrayList<>()).add(uid);
            }
        }
        
        // 批量推送到各节点
        nodeMap.forEach((nodeIp, uidList) -> {
            if (nodeIp.equals(getLocalIp())) {
                uidList.forEach(uid -> webSocketService.sendMsgLocal(uid, msg));
            } else {
                webSocketRpc.batchSendMsg(nodeIp, uidList, msg);
            }
        });
    }
}
```

### 3.3 性能分析

**单聊场景：**
- ✅ **高效**：查Redis → 精准推送，1次即可
- ✅ **延迟低**：<10ms

**群聊场景（万人群）：**
- ❌ **扇出爆炸**：需要10000次查询Redis
- ❌ **消息副本多**：10000份消息传输
- ❌ **延迟叠加**：P99可能达到5秒+

**消息传输次数计算：**
```
假设10000人在线，分布在10个节点

精准投递：
- 消息副本：10000份（每人一份）
- 传输次数：10000次（Router → 各节点）
- 网络IO：10000 * 消息大小
```

### 3.4 存在的问题

#### **问题1：连接数爆炸**

```
假设：
- 1000台WebSocket节点
- 1000台Router节点

连接数 = 1000 * 1000 = 100万条TCP连接！
```

**解决方案：分层路由**

```
┌─────────────────────────────────┐
│     二级路由（减少连接数）       │
├─────────────────────────────────┤
│  Router → 一级路由（10台）       │
│         → 二级路由（100台）      │
│         → WebSocket（1000台）    │
│                                  │
│  连接数：10*100 + 100*1000       │
│        = 1000 + 100000           │
│        = 101000（减少90%）       │
└─────────────────────────────────┘
```

#### **问题2：消息扇出压力**

万人群聊：
- 10000次Redis查询
- 10000次消息推送
- 单点Router压力巨大

#### **问题3：延迟叠加**

即使多线程并发推送，总体延迟依然很高：
- Redis查询：10ms * 10000 / 线程数
- 消息推送：5ms * 10000 / 线程数

## 四、集群广播方案详解

### 4.1 核心思想

**革命性改变：**
- ❌ 不再查询用户位置
- ❌ 不再精准推送
- ✅ MQ广播到所有节点
- ✅ 各节点本地过滤

```
┌──────────────────────────────────────────┐
│           集群广播架构                    │
└──────────────────────────────────────────┘

1. 发送消息
   ↓
┌─────────────────────────────────────┐
│  IM服务 → MQ（广播模式）              │
│  Topic: push_msg                      │
│  消息体: {uids: [1001,1002...], msg}  │
└─────────────────────────────────────┘

2. 所有节点接收
   ↓
┌─────────────────────────────────────┐
│  节点1、节点2、节点3... 都收到消息     │
│  （RocketMQ BROADCASTING模式）        │
└─────────────────────────────────────┘

3. 本地过滤推送
   ↓
┌─────────────────────────────────────┐
│  节点1: 检查uids，只推送本地用户      │
│  节点2: 检查uids，只推送本地用户      │
│  节点3: 检查uids，只推送本地用户      │
└─────────────────────────────────────┘
```

### 4.2 核心代码

#### **MQ生产者（广播发送）**

```java
@Service
public class PushService {
    @Autowired
    private RocketMQTemplate rocketMQTemplate;
    
    // 群聊推送
    public void sendGroupMsg(List<Long> uids, WSBaseResp msg) {
        PushMessageDTO dto = PushMessageDTO.builder()
            .uidList(uids)
            .msg(msg)
            .build();
        
        // 发送到MQ（只发送一次）
        rocketMQTemplate.syncSend(
            MQConstant.PUSH_TOPIC, 
            dto
        );
    }
}
```

#### **MQ消费者（广播消费）**

```java
@Component
@RocketMQMessageListener(
    topic = MQConstant.PUSH_TOPIC,
    consumerGroup = "push_group",
    messageModel = MessageModel.BROADCASTING  // ✅ 关键：广播模式
)
public class PushConsumer implements RocketMQListener<PushMessageDTO> {
    @Autowired
    private WebSocketService webSocketService;
    
    @Override
    public void onMessage(PushMessageDTO dto) {
        // 获取本地在线用户
        Set<Long> localOnlineUids = webSocketService.getLocalOnlineUids();
        
        // 过滤：只处理本地在线的用户
        dto.getUidList().stream()
            .filter(localOnlineUids::contains)  // ✅ 本地过滤
            .forEach(uid -> {
                webSocketService.sendMsgLocal(uid, dto.getMsg());
            });
    }
}
```

#### **本地连接管理**

```java
@Component
public class WebSocketService {
    // 本地连接管理
    private static final Map<Long, Channel> ONLINE_MAP = new ConcurrentHashMap<>();
    
    // 获取本地在线用户
    public Set<Long> getLocalOnlineUids() {
        return ONLINE_MAP.keySet();
    }
    
    // 本地推送
    public void sendMsgLocal(Long uid, WSBaseResp msg) {
        Channel channel = ONLINE_MAP.get(uid);
        if (channel != null) {
            channel.writeAndFlush(new TextWebSocketFrame(JSONUtil.toJsonStr(msg)));
        }
    }
}
```

### 4.3 性能分析

**万人群聊对比：**

| 维度 | 精准投递 | 集群广播 |
|-----|---------|---------|
| **MQ发送次数** | 10000次 | 1次 |
| **消息副本** | 10000份 | 10份（节点数） |
| **Redis查询** | 10000次 | 0次 |
| **扇出压力** | 单点压力大 | 分散到各节点 |
| **网络IO** | uid+消息 * 10000 | (uid * 10000 + 消息) * 10 |

**消息传输公式：**

```
精准投递：
消息传输 = u * 3份（u=在线人数，3=链路层数）

集群广播：
消息传输 = u + n份（u=在线人数，n=节点数）

示例：10000人在线，10个节点
- 精准投递：10000 * 3 = 30000份消息
- 集群广播：10000 + 10 = 10010份消息

节省：(30000 - 10010) / 30000 = 66.6%
```

### 4.4 优缺点分析

**优点：**
- ✅ **无需Router**：省去中心化服务
- ✅ **无扇出压力**：MQ只发送1次
- ✅ **消息副本少**：大群聊节省90%+
- ✅ **延迟稳定**：无叠加延迟

**缺点：**
- ❌ **小群/单聊浪费**：所有节点都收到，本地过滤浪费IO
- ❌ **网络IO浪费**：不属于本节点的消息也被拉取
- ❌ **CPU浪费**：反序列化后才过滤

## 五、性能优化策略

### 5.1 优化1：消息副本优化

**问题：**
万人群聊，每人的消息内容都一样，为什么要发送10000份完整消息？

**优化方案：共享消息体**

```java
// ❌ 优化前：拆分发送（消息副本多）
for (Long uid : uids) {
    PushMessageDTO dto = new PushMessageDTO(uid, msg);
    mqProducer.send(dto);  // 发送10000次
}

// ✅ 优化后：批量发送（共享消息体）
PushMessageDTO dto = PushMessageDTO.builder()
    .uidList(uids)  // 只传uid列表
    .msg(msg)       // 消息体共享
    .build();
mqProducer.send(dto);  // 只发送1次
```

**效果对比：**

```
假设：
- 10000人在线
- 10个节点
- uid = 8字节
- 消息体 = 1KB

优化前：
- 总传输 = (8字节 + 1KB) * 10000 * 10 = 100MB

优化后：
- 总传输 = (8字节 * 10000 + 1KB) * 10 = 0.78MB + 10KB ≈ 0.8MB

节省：(100 - 0.8) / 100 = 99.2%！
```

---

### 5.2 优化2：消息过滤优化

**问题：**
所有节点都拉取消息，本地过滤浪费：
- 网络IO：不属于本节点的消息也传输
- CPU：反序列化后才过滤

**方案1：Header过滤（节省CPU）**

```java
// 生产者：uid列表放到Header
Message message = MessageBuilder
    .withPayload(msg)
    .setHeader("uids", JSONUtil.toJsonStr(uids))  // ✅ Header存uid
    .build();
mqProducer.send(message);

// 消费者：Header预过滤
@RocketMQMessageListener(
    selectorExpression = "uid in ('1001','1002')"  // SQL过滤表达式
)
public class PushConsumer implements RocketMQListener<Message> {
    @Override
    public void onMessage(Message message) {
        // Header已过滤，直接处理
        String uidsStr = message.getHeaders().get("uids");
        List<Long> uids = JSONUtil.toList(uidsStr, Long.class);
        // ... 推送
    }
}
```

**限制：**
- Header有大小限制（一般4KB）
- 大群聊uid列表超限，需要分批

**方案2：Broker端过滤（节省IO）**

RocketMQ支持SQL92表达式过滤：

```java
// 消费者订阅时指定过滤条件
@RocketMQMessageListener(
    topic = "push_msg",
    selectorType = SelectorType.SQL92,
    selectorExpression = "uids LIKE '%1001%' OR uids LIKE '%1002%'"
)
```

**问题：**
- WebSocket连接动态变化，SQL表达式无法动态更新
- 需要魔改RocketMQ源码支持动态过滤

---

### 5.3 优化3：混合方案

**核心思想：扬长避短**

```java
@Service
public class SmartPushService {
    
    public void sendMsg(List<Long> uids, WSBaseResp msg) {
        // 阈值：50人
        if (uids.size() > 50) {
            // 大群：集群广播
            sendByBroadcast(uids, msg);
        } else {
            // 小群/单聊：精准推送
            sendByPrecise(uids, msg);
        }
    }
    
    // 集群广播
    private void sendByBroadcast(List<Long> uids, WSBaseResp msg) {
        PushMessageDTO dto = PushMessageDTO.builder()
            .uidList(uids)
            .msg(msg)
            .build();
        mqProducer.sendBroadcast(dto);
    }
    
    // 精准推送
    private void sendByPrecise(List<Long> uids, WSBaseResp msg) {
        uids.forEach(uid -> {
            String nodeIp = redisTemplate.opsForValue().get("ws:uid:" + uid);
            if (nodeIp != null) {
                routerService.sendMsg(nodeIp, uid, msg);
            }
        });
    }
}
```

**效果：**
- 单聊/小群：精准推送，效率高
- 大群：集群广播，消息副本少
- 综合最优解

## 六、百万级直播推送方案

### 6.1 极端场景

**场景描述：**
- 100万人在线直播间
- 大量礼物、弹幕、互动消息
- 要求：实时推送（<100ms）

**挑战：**
- 精准推送：100万次扇出，不可行
- 集群广播：假设需要500台WebSocket，也需要500次消息副本

### 6.2 解决方案：热点直播间隔离

```
┌──────────────────────────────────────────┐
│        热点直播间隔离方案                 │
└──────────────────────────────────────────┘

1. 热点识别
   ↓
┌─────────────────────────────────────┐
│  直播间人数 > 10000 → 标记为热点      │
└─────────────────────────────────────┘

2. 专属WebSocket集群
   ↓
┌─────────────────────────────────────┐
│  动态扩容：启动500台专属WebSocket      │
│  网关路由：该直播间流量路由到专属集群  │
└─────────────────────────────────────┘

3. 集群广播推送
   ↓
┌─────────────────────────────────────┐
│  MQ广播到500台专属WebSocket           │
│  消息副本：只需500份                  │
└─────────────────────────────────────┘
```

### 6.3 核心实现

#### **热点升级流程**

```java
@Service
public class HotRoomService {
    
    // 检测热点
    @Scheduled(fixedRate = 60000)  // 每分钟检测
    public void checkHotRoom() {
        List<Room> rooms = roomDao.getActiveRooms();
        
        for (Room room : rooms) {
            Long onlineCount = getOnlineCount(room.getId());
            
            if (onlineCount > 10000 && !room.isHot()) {
                // 升级为热点直播间
                upgradeToHot(room);
            }
        }
    }
    
    // 升级热点
    private void upgradeToHot(Room room) {
        // 1. 标记为热点
        room.setHot(true);
        roomDao.updateById(room);
        
        // 2. K8s动态扩容WebSocket
        k8sService.scaleUp("hot-websocket", 500);
        
        // 3. 等待节点Ready
        Thread.sleep(30000);
        
        // 4. 更新网关路由规则
        gatewayService.addRoute(room.getId(), "hot-websocket");
        
        // 5. 断开现有连接，强制重连到新集群
        sendReconnectNotice(room.getId());
    }
    
    // 发送重连通知
    private void sendReconnectNotice(Long roomId) {
        WSBaseResp resp = WSAdapter.buildReconnectMsg();
        List<Long> uids = getRoomUsers(roomId);
        pushService.sendMsg(uids, resp);
    }
}
```

## 七、消息时序性保证

### 7.1 问题场景

```
用户A快速发送3条消息：
1. "你好"
2. "在吗"
3. "有空吗"

问题：服务端接收可能是：
- "你好" → "有空吗" → "在吗" ❌ 顺序错乱
```

### 7.2 解决方案

#### **方案1：客户端排序（单聊场景）**

```java
// 客户端发送时带上序列号
public class ChatMessage {
    private Long seq;      // 本地自增序列号
    private Long timestamp; // 发送时间戳
    private String content;
}

// 服务端存储
@Data
public class Message {
    private Long id;           // 全局唯一ID
    private Long seq;          // 客户端序列号
    private Long createTime;   // 服务端时间（毫秒）
}

// 前端展示时排序
messages.sort((a, b) -> {
    // 先按服务端时间排序
    int timeCompare = a.createTime.compareTo(b.createTime);
    if (timeCompare != 0) {
        return timeCompare;
    }
    // 同一秒内按客户端seq排序
    return a.seq.compareTo(b.seq);
});
```

**限制：**
- 只适合单聊（同一个用户的消息）
- 群聊场景不适用（每人seq不同）

---

#### **方案2：服务端排序（群聊场景）**

```sql
-- 消息表设计
CREATE TABLE `message` (
  `id` BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,  -- ✅ 全局唯一，严格递增
  `room_id` BIGINT,
  `from_uid` BIGINT,
  `content` TEXT,
  `create_time` DATETIME(3),  -- 毫秒精度
  KEY `idx_room_time` (`room_id`, `create_time`)
) ENGINE=InnoDB;
```

**排序策略：**

```java
// 查询消息（按ID排序）
public List<Message> getMessages(Long roomId, Long cursor, Integer pageSize) {
    return messageDao.selectList(
        new LambdaQueryWrapper<Message>()
            .eq(Message::getRoomId, roomId)
            .lt(cursor != null, Message::getId, cursor)  // ✅ ID作为游标
            .orderByDesc(Message::getId)  // ✅ ID保证全局有序
            .last("LIMIT " + pageSize)
    );
}
```

**为什么用ID而不是时间戳？**

| 维度 | ID | 时间戳（毫秒） |
|-----|-------|--------------|
| **唯一性** | ✅ 保证唯一 | ❌ 毫秒内可能重复 |
| **有序性** | ✅ 严格递增 | ✅ 递增（可能重复） |
| **游标翻页** | ✅ 完美支持 | ❌ 需要额外字段 |

---

### 7.3 最佳实践

**推荐方案：服务端ID + 毫秒时间戳**

```java
@Data
@TableName("message")
public class Message {
    @TableId(type = IdType.AUTO)
    private Long id;  // ✅ 核心：全局唯一、严格递增
    
    @TableField("create_time")
    private Date createTime;  // DATETIME(3) 毫秒精度
}

// 查询时只按ID排序
List<Message> messages = messageDao.selectList(
    new LambdaQueryWrapper<Message>()
        .eq(Message::getRoomId, roomId)
        .orderByDesc(Message::getId)  // 只按ID排序即可
);
```

**优势：**
- ✅ 简单：只需一个字段保证时序
- ✅ 高效：ID是主键，查询最快
- ✅ 通用：单聊、群聊都适用

### 8.2 精准投递和集群广播如何选择？

**【对比分析回答】**

| 场景 | 推荐方案 | 理由 |
|-----|---------|------|
| **单聊为主** | 精准投递 | 只推送1人，效率最高 |

```java
public PushStrategy choosePushStrategy(int onlineUserCount, int nodeCount) {
    // 计算消息传输成本
    int preciseCost = onlineUserCount * 3;  // 精准投递：u * 3份
    int broadcastCost = onlineUserCount + nodeCount;  // 集群广播：u + n份
    
    return preciseCost < broadcastCost 
        ? PushStrategy.PRECISE  // 精准投递
        : PushStrategy.BROADCAST;  // 集群广播
}
```

### 8.5 RocketMQ的广播模式如何工作？

**【技术细节回答】**

**核心原理：**

```java
// 广播模式 vs 集群模式对比

// ❌ 集群模式（CLUSTERING）- 负载均衡
@RocketMQMessageListener(
    topic = "push_msg",
    consumerGroup = "push_group",
    messageModel = MessageModel.CLUSTERING  // 默认
)
// 特点：每条消息只被一个消费者消费（负载均衡）

// ✅ 广播模式（BROADCASTING）- 所有节点接收
@RocketMQMessageListener(
    topic = "push_msg",
    consumerGroup = "push_group",
    messageModel = MessageModel.BROADCASTING  // 广播
)
// 特点：每条消息被所有消费者消费
```

**消息流转：**

```
生产者 → Broker → 消费者
              ↓
        ┌─────┴─────┬─────┬─────┐
        ↓           ↓     ↓     ↓
      节点1        节点2  节点3  节点4
      (都收到)    (都收到)
```

**关键实现：**

```java
@Component
@RocketMQMessageListener(
    topic = MQConstant.PUSH_TOPIC,
    consumerGroup = "websocket_push_group",
    messageModel = MessageModel.BROADCASTING,  // ✅ 广播模式
    consumeThreadMax = 50  // 消费线程数
)
public class PushConsumer implements RocketMQListener<PushMessageDTO> {
    
    @Autowired
    private WebSocketService webSocketService;
    
    @Override
    public void onMessage(PushMessageDTO dto) {
        // 1. 获取本地在线用户
        Set<Long> localOnlineUids = webSocketService.getLocalOnlineUids();
        
        // 2. 本地过滤（只推送本地在线的用户）
        dto.getUidList().stream()
            .filter(localOnlineUids::contains)  // 本地过滤
            .forEach(uid -> {
                webSocketService.sendMsgLocal(uid, dto.getMsg());
            });
    }
}
```

**注意事项：**
1. **消费进度不保存**：广播模式不保存消费进度，重启会重复消费
2. **消息堆积**：如果消费慢，会导致消息堆积
3. **网络IO**：所有节点都拉取消息，需要优化消息大小

```java
public class UserLocationCache {

    private final Cache<Long, String> localCache = Caffeine.newBuilder()

        }
    }
}
```

### 8.7 消息副本优化的原理是什么？

**【深度技术回答】**

**优化前（拆分发送）：**

```java
// ❌ 每人一条消息，消息副本多
for (Long uid : uids) {
    PushMessageDTO dto = new PushMessageDTO();
    dto.setUid(uid);
    dto.setMsg(msg);  // 每次都复制整个msg对象
    mqProducer.send("push_topic", dto);
}
```

**问题分析：**

```
假设：10000人在线，10个WebSocket节点

消息结构：
{
  "uid": 1001,
  "msg": {
    "type": 1,
    "content": "你好",
    "fromUid": 123,
    "msgId": 456789,
    "extra": {...}  // 可能很大
  }
}

传输量计算：
- 单条消息大小：8字节(uid) + 1KB(msg) ≈ 1KB
- 总传输量：1KB * 10000条 * 10节点 = 100MB
```

**优化后（批量发送）：**

```java
// ✅ uid列表 + 共享消息体
PushMessageDTO dto = new PushMessageDTO();
dto.setUidList(uids);  // [1001, 1002, 1003, ...]
dto.setMsg(msg);  // 只有一份msg
mqProducer.send("push_topic", dto);
```

**优化效果：**

```
消息结构：
{
  "uidList": [1001, 1002, 1003, ...],  // 10000个uid
  "msg": {
    "type": 1,
    "content": "你好",
    "fromUid": 123,
    "msgId": 456789,
    "extra": {...}
  }
}

传输量计算：
- uidList大小：8字节 * 10000 = 78KB
- msg大小：1KB
- 单条消息总大小：78KB + 1KB ≈ 79KB
- 总传输量：79KB * 10节点 = 790KB

节省：(100MB - 790KB) / 100MB ≈ 99.2%！
```

**核心原理：**
1. **消息体共享**：10000人收到的msg内容完全一样，只传输一次
2. **uid压缩**：只传uid列表（Long数组），占用空间小
3. **批量传输**：MQ只发送一次，而非10000次

**进一步优化：**

```java
// uid压缩（BitSet）
BitSet uidBitSet = new BitSet();
uids.forEach(uid -> uidBitSet.set(uid.intValue()));
byte[] compressedUids = uidBitSet.toByteArray();

// 10000个uid，原本80KB，压缩后可能只有1-2KB
```

- ✅ 消息副本少

- ❌ 小群/单聊有浪费

**公式：**

- 集群广播：`在线人数 + 节点数`（uid列表+节点副本）
- 热点隔离：`节点数`（专属集群）

```java
@Component
@Slf4j
public class WebSocketService {
    
    // 本地连接管理
    private static final ConcurrentHashMap<Long, Channel> ONLINE_MAP = new ConcurrentHashMap<>();
    
    @Autowired
    private PushService pushService;
    
    /**
     * 用户上线
     */
    public void online(Long uid, Channel channel) {
        ONLINE_MAP.put(uid, channel);
        log.info("用户上线：uid={}, 当前在线人数={}", uid, ONLINE_MAP.size());
        
        // 通知好友上线
        pushService.sendOnlineNotice(uid);
    }
    
    /**
     * 用户下线
     */
    public void offline(Long uid) {
        ONLINE_MAP.remove(uid);
        log.info("用户下线：uid={}, 当前在线人数={}", uid, ONLINE_MAP.size());
        
        // 通知好友下线
        pushService.sendOfflineNotice(uid);
    }
    
    /**
     * 本地推送（单个用户）
     */
    public void sendMsgLocal(Long uid, WSBaseResp msg) {
        Channel channel = ONLINE_MAP.get(uid);
        if (channel != null && channel.isActive()) {
            try {
                channel.writeAndFlush(new TextWebSocketFrame(JSONUtil.toJsonStr(msg)));
                log.debug("本地推送成功：uid={}, msg={}", uid, msg.getType());
            } catch (Exception e) {
                log.error("本地推送失败：uid={}", uid, e);
            }
        }
    }
    
    /**
     * 批量本地推送
     */
    public void sendMsgBatchLocal(List<Long> uids, WSBaseResp msg) {
        String msgJson = JSONUtil.toJsonStr(msg);
        TextWebSocketFrame frame = new TextWebSocketFrame(msgJson);
        
        uids.forEach(uid -> {
            Channel channel = ONLINE_MAP.get(uid);
            if (channel != null && channel.isActive()) {
                channel.writeAndFlush(frame.retain());
            }
        });
        frame.release();
    }
    
    /**
     * 获取本地在线用户
     */
    public Set<Long> getLocalOnlineUids() {
        return ONLINE_MAP.keySet();
    }
    
    /**
     * 检查用户是否在线
     */
    public boolean isOnline(Long uid) {
        return ONLINE_MAP.containsKey(uid);
    }
}
```

```java
@Service
@Slf4j
public class SmartPushService {
    
    @Autowired
    private RocketMQTemplate rocketMQTemplate;
    @Autowired
    private RedisTemplate<String, String> redisTemplate;
    @Autowired
    private WebSocketService webSocketService;
    
    // 阈值配置
    private static final int BROADCAST_THRESHOLD = 50;  // 50人以上用广播
    
    /**
     * 智能推送（自动选择策略）
     */
    public void sendMsg(List<Long> uids, WSBaseResp msg) {
        if (CollectionUtils.isEmpty(uids)) {
            return;
        }
        
        if (uids.size() >= BROADCAST_THRESHOLD) {
            // 大群：集群广播
            log.info("采用集群广播策略：uidCount={}", uids.size());
            sendByBroadcast(uids, msg);
        } else {
            // 小群/单聊：精准推送
            log.info("采用精准推送策略：uidCount={}", uids.size());
            sendByPrecise(uids, msg);
        }
    }
    
    /**
     * 集群广播
     */
    private void sendByBroadcast(List<Long> uids, WSBaseResp msg) {
        PushMessageDTO dto = PushMessageDTO.builder()
            .uidList(uids)
            .msg(msg)
            .build();
        
        // 发送到MQ（只发送1次）
        rocketMQTemplate.syncSend(MQConstant.PUSH_TOPIC, dto);
    }
    
    /**
     * 精准推送
     */
    private void sendByPrecise(List<Long> uids, WSBaseResp msg) {
        // 按节点分组
        Map<String, List<Long>> nodeMap = new HashMap<>();
        
        for (Long uid : uids) {
            // 查询用户所在节点
            String nodeIp = redisTemplate.opsForValue().get("ws:uid:" + uid);
            if (nodeIp != null) {
                nodeMap.computeIfAbsent(nodeIp, k -> new ArrayList<>()).add(uid);
            }
        }
        
        // 批量推送到各节点
        String localIp = getLocalIp();
        nodeMap.forEach((nodeIp, uidList) -> {
            if (nodeIp.equals(localIp)) {
                // 本地推送
                uidList.forEach(uid -> webSocketService.sendMsgLocal(uid, msg));
            } else {
                // 远程推送（通过Dubbo/HTTP）
                remoteWebSocketService.batchSendMsg(nodeIp, uidList, msg);
            }
        });
    }
    
    private String getLocalIp() {
        // 获取本机IP
        return "10.102.1.1";
    }
}
```

### 12.1 策略模式（Strategy Pattern）

**应用场景：推送策略选择**

```java
/**
 * 推送策略接口
 */
public interface PushStrategy {
    /**
     * 推送消息
     */
    void push(List<Long> uids, WSBaseResp msg);
    
    /**
     * 是否支持该场景
     */
    boolean support(PushContext context);
}

/**
 * 精准推送策略
 */
@Component
public class PrecisePushStrategy implements PushStrategy {
    
    @Override
    public void push(List<Long> uids, WSBaseResp msg) {
        // 精准推送逻辑
        uids.forEach(uid -> {
            String nodeIp = getNodeByUid(uid);
            sendToNode(nodeIp, uid, msg);
        });
    }
    
    @Override
    public boolean support(PushContext context) {
        // 单聊或小群聊
        return context.getUidCount() < 50;
    }
}

/**
 * 广播推送策略
 */
@Component
public class BroadcastPushStrategy implements PushStrategy {
    
    @Override
    public void push(List<Long> uids, WSBaseResp msg) {
        // 广播推送逻辑
        mqProducer.sendBroadcast(new PushMessageDTO(uids, msg));
    }
    
    @Override
    public boolean support(PushContext context) {
        // 大群聊
        return context.getUidCount() >= 50;
    }
}

/**
 * 策略工厂
 */
@Component
public class PushStrategyFactory {
    
    @Autowired
    private List<PushStrategy> strategies;
    
    public PushStrategy getStrategy(PushContext context) {
        return strategies.stream()
            .filter(strategy -> strategy.support(context))
            .findFirst()
            .orElseThrow(() -> new BusinessException("未找到合适的推送策略"));
    }
}

/**
 * 推送服务
 */
@Service
public class PushService {
    
    @Autowired
    private PushStrategyFactory strategyFactory;
    
    public void sendMsg(List<Long> uids, WSBaseResp msg) {
        PushContext context = new PushContext(uids.size());
        PushStrategy strategy = strategyFactory.getStrategy(context);
        strategy.push(uids, msg);
    }
}
```

- ✅ **开闭原则**：新增推送策略无需修改现有代码
- ✅ **单一职责**：每个策略专注于一种推送方式
- ✅ **易于扩展**：可轻松添加热点隔离、优先级等策略

### 12.3 模板方法模式（Template Method Pattern）

**应用场景：消息推送统一流程**

```java
/**
 * 抽象推送模板
 */
public abstract class AbstractPushTemplate {
    
    /**
     * 推送消息（模板方法）
     */
    public final void push(List<Long> uids, WSBaseResp msg) {
        // 1. 前置校验
        if (!validate(uids, msg)) {
            return;
        }
        
        // 2. 过滤离线用户
        List<Long> onlineUids = filterOnlineUsers(uids);
        
        // 3. 构建推送DTO
        PushMessageDTO dto = buildPushDTO(onlineUids, msg);
        
        // 4. 执行推送（子类实现）
        doPush(dto);
        
        // 5. 离线推送
        List<Long> offlineUids = getOfflineUsers(uids, onlineUids);
        if (!offlineUids.isEmpty()) {
            doOfflinePush(offlineUids, msg);
        }
        
        // 6. 推送日志记录
        logPush(dto);
    }
    
    /**
     * 校验（钩子方法）
     */
    protected boolean validate(List<Long> uids, WSBaseResp msg) {
        return !CollectionUtils.isEmpty(uids) && msg != null;
    }
    
    /**
     * 过滤在线用户（可覆盖）
     */
    protected List<Long> filterOnlineUsers(List<Long> uids) {
        return uids.stream()
            .filter(uid -> redisTemplate.hasKey("ws:uid:" + uid))
            .collect(Collectors.toList());
    }
    
    /**
     * 构建推送DTO（可覆盖）
     */
    protected PushMessageDTO buildPushDTO(List<Long> uids, WSBaseResp msg) {
        return PushMessageDTO.builder()
            .uidList(uids)
            .msg(msg)
            .build();
    }
    
    /**
     * 执行推送（抽象方法，子类必须实现）
     */
    protected abstract void doPush(PushMessageDTO dto);
    
    /**
     * 离线推送（钩子方法）
     */
    protected void doOfflinePush(List<Long> offlineUids, WSBaseResp msg) {
        // 默认实现：发送APP离线推送
        log.info("离线推送：offlineUids={}", offlineUids);
    }
    
    /**
     * 推送日志（钩子方法）
     */
    protected void logPush(PushMessageDTO dto) {
        log.info("推送消息：uidCount={}, msgType={}", 
            dto.getUidList().size(), dto.getMsg().getType());
    }
    
    private List<Long> getOfflineUsers(List<Long> allUids, List<Long> onlineUids) {
        Set<Long> onlineSet = new HashSet<>(onlineUids);
        return allUids.stream()
            .filter(uid -> !onlineSet.contains(uid))
            .collect(Collectors.toList());
    }
}

/**
 * 广播推送实现
 */
@Component
public class BroadcastPushTemplate extends AbstractPushTemplate {
    
    @Autowired
    private RocketMQTemplate rocketMQTemplate;
    
    @Override
```
