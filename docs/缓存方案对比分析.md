## 三种方案概述

### 方案1：二级缓存（已提交）
**架构**：自研批量缓存框架 + Redis
```
业务代码 → AbstractRedisStringCache → Redis → 数据库
```

**核心特点**：
- ✅ 使用模板方法模式封装批量查询逻辑
- ✅ Redis MGET/MSET 批量操作
- ✅ 自动差集计算和回写
- ✅ 代码复用率高（90%+）

**代码示例**：
```java
@Component
public class UserInfoCache extends AbstractRedisStringCache<Long, User> {
    @Override
    protected String getKey(Long uid) {
        return "user:info:" + uid;
    }
    
    @Override
    protected Map<Long, User> load(List<Long> uidList) {
        return userDao.listByIds(uidList);
    }
}
```

---

### 方案2：JetCache多级缓存（未提交，备选）
**架构**：Caffeine本地缓存 + Redis远程缓存
```
业务代码 → @Cached注解 → Caffeine(1分钟) → Redis(30分钟) → 数据库
```

**核心特点**：
- ✅ 阿里开源框架，成熟稳定
- ✅ 自动管理两级缓存
- ✅ 支持注解式和编程式
- ✅ 内置统计和监控

**代码示例**：
```java
@Cached(
    name = "user:info:",
    key = "#userId",
    expire = 1800,              // Redis 30分钟
    cacheType = CacheType.BOTH, // 两级缓存
    localExpire = 60,           // 本地 1分钟
    cacheNullValue = true       // 防止缓存穿透
)
public User getUserInfo(Long userId) {
    return userDao.getById(userId);
}
```

---

### 方案3：Feed三级缓存（新方案）
**架构**：Caffeine + Redis页面缓存 + Redis片段缓存 + 热点探测
```
业务代码 → Caffeine(热点数据) → Redis页面缓存 → Redis片段缓存 → 数据库
         ↑
    HotKey探测机制（动态延长TTL）
```

**核心特点**：
- ✅ 三级缓存分层
- ✅ 自定义热点探测（HotKey Detection）
- ✅ 动态TTL延长（热点数据缓存更久）
- ✅ 随机抖动防雪崩
- ✅ Single-Flight防击穿

**架构图**：
```
┌─────────────────────────────────────────────────────────┐
│                    业务层                                │
└────────────────────┬────────────────────────────────────┘
                     │
        ┌────────────┴────────────┐
        │   HotKey探测器           │
        │  - 访问计数              │
        │  - 热度评分              │
        │  - 动态TTL调整           │
        └────────────┬────────────┘
                     │
┌────────────────────┴────────────────────────────────────┐
│                  L1: Caffeine本地缓存                    │
│  - 仅缓存热点数据（访问频率 > 阈值）                      │
│  - TTL: 1-5分钟（根据热度动态调整）                       │
│  - 容量: 1000条                                          │
└────────────────────┬────────────────────────────────────┘
                     │ 未命中
┌────────────────────┴────────────────────────────────────┐
│              L2: Redis页面缓存（整页）                    │
│  - 缓存完整的页面数据（如会话列表）                       │
│  - TTL: 5-30分钟（根据热度 + 随机抖动）                   │
│  - Key: page:contact:list:uid:123                       │
└────────────────────┬────────────────────────────────────┘
                     │ 未命中
┌────────────────────┴────────────────────────────────────┐
│            L3: Redis片段缓存（细粒度）                    │
│  - 缓存单个实体（如用户信息、房间信息）                   │
│  - TTL: 30-60分钟（根据热度 + 随机抖动）                  │
│  - Key: user:info:123, room:info:456                    │
└────────────────────┬────────────────────────────────────┘
                     │ 未命中
                ┌────┴────┐
                │  数据库  │
                └─────────┘
```

#### 第2步：优化批量查询（1天）

**问题**：JetCache的@Cached注解不直接支持批量查询

**解决方案**：使用编程式API + SingleFlight

```java
@Component
public class UserInfoCache {
    @Autowired
    private UserDao userDao;
    
    @Autowired
    private SingleFlight singleFlight;
    
    // 单个查询（注解式）
    @Cached(
        name = "user:info:",
        key = "#userId",
        expire = 1800,
        cacheType = CacheType.BOTH,
        localExpire = 60,
        cacheNullValue = true
    )
    public User getUserInfo(Long userId) {
        return userDao.getById(userId);
    }
    
    // 批量查询（编程式 + SingleFlight）
    public Map<Long, User> getUserInfoBatch(List<Long> userIds) {
        // 创建缓存实例
        Cache<Long, User> cache = JetCacheUtils.create(
            "user:info:",
            Duration.ofMinutes(30)
        );
        
        Map<Long, User> result = new HashMap<>();
        List<Long> missIds = new ArrayList<>();
        
        // 1. 批量查询缓存
        for (Long userId : userIds) {
            User user = cache.get(userId);
            if (user != null) {
                result.put(userId, user);
            } else {
                missIds.add(userId);
            }
        }
        
        // 2. 批量加载未命中的数据（使用SingleFlight防击穿）
        if (!missIds.isEmpty()) {
            String key = "user:batch:" + missIds.hashCode();
            Map<Long, User> loadedUsers = singleFlight.execute(key, () -> {
                List<User> users = userDao.listByIds(missIds);
                return users.stream()
                    .collect(Collectors.toMap(User::getId, Function.identity()));
            });
            
            // 3. 批量写入缓存
            loadedUsers.forEach(cache::put);
            result.putAll(loadedUsers);
        }
        
        return result;
    }
}
```

@Component
public class HotKeyDetector {
    private final Cache<String, AtomicLong> accessCounter = 
        Caffeine.newBuilder()
            .maximumSize(10000)
            .expireAfterWrite(1, TimeUnit.MINUTES)
            .build();
    
    public boolean isHotKey(String key) {
        AtomicLong count = accessCounter.get(key, k -> new AtomicLong(0));
        long accessCount = count.incrementAndGet();
        
        // 1分钟内访问超过100次，认为是热点
        return accessCount > 100;
    }
}
