## 一、文档归集约定（必读）

### 1.1 约定说明

**所有项目相关文档必须统一放置在 `docs/` 目录下**，禁止分散存放在以下位置：
- ❌ `.learnings/` → 已迁移到本文档「学习记录」章节
- ❌ 各模块根目录的零散 `.md` 文件 → 已迁移/引用到本文档
- ❌ 临时笔记文件 → 统一归档到 `docs/项目笔记.md`

### 1.2 文档存放规范

| 文档类型 | 存放位置 | 命名规范 |
|---------|---------|---------|
| 技术方案/架构设计 | `docs/` 根目录 | `XX技术方案.md` |
| 面试准备材料 | `docs/` 根目录 | `面试准备-XX.md` |
| AI模块专项文档 | `mallchat-ai/docs/` | 按模块分子目录 |
| 学习记录/复盘 | `docs/项目笔记.md` 或本文档对应章节 | 按时间线组织 |
| 交付物清单 | `docs/交付物清单.md` | 统一命名 |
| 快速参考卡 | `docs/` 根目录 | `XX快速参考卡.md` |

### 1.3 为什么这么做

1. **统一入口**：新成员/面试官/自己回顾时，只需看这一个文档就能找到所有资料
2. **防止丢失**：分散的文档容易被遗忘，难以维护
3. **知识传承**：项目交接时，完整的文档体系是最大资产
4. **面试准备**：面试前快速复习，按图索骥

**类型**: best_practice  
**日期**: 2026-05-31  
**优先级**: high  
**状态**: resolved  
**领域**: backend / AI

#### 内容摘要

用户要求将项目 AI 技术栈从 OpenAI/Milvus/ChatGLM 方案全面替换为本地开源方案。

**技术选型确认**：
| 组件 | 推荐方案 | 备选方案 | 部署方式 |
|------|---------|---------|---------|
| Embedding | bge-large-zh-v1.5 | m3e-base | Ollama本地 |
| 向量数据库 | Qdrant | Milvus | Docker本地 |
| 大模型 | Qwen2.5-14B | Llama3-70B | Ollama本地 |

**关键实现决策**：
1. LangChain4j 升级：0.27.1 → 0.36.0
2. Qdrant 动态向量解决维度兼容问题（1024维 vs 768维）
3. Mock模式设计：无需外部依赖即可启动项目
4. Java ↔ Python 跨语言通信：FastAPI REST桥接

**交付物**：
- 代码：QdrantVectorService、QwenLLMService、LlamaLLMService、OllamaBgeEmbeddingService、M3eEmbeddingService、Mock系列实现
- 文档：AI技术方案.md、BadCase与面试谈资.md、项目Review与优化建议.md

## 五、Mock模式使用指南

### 5.1 为什么需要Mock模式

- 无需部署 Ollama、Qdrant 即可启动项目
- 适合本地学习、面试准备、代码调试
- 启动速度快，无外部依赖

### 5.2 启动方式

```bash
# 方式1：修改 application.yml
spring:
  profiles:
    active: mock

# 方式2：启动参数
mvn spring-boot:run -Dspring-boot.run.profiles=mock

# 方式3：IDE配置
VM options: -Dspring.profiles.active=mock
```

### 5.3 Mock行为说明

| 组件 | Mock行为 | 说明 |
|------|---------|------|
| LLM | 返回固定模拟回复 | 支持流式/非流式 |
| Embedding | MD5哈希生成确定性向量 | 1024维，同文本同向量 |
| Vector | 内存存储+余弦相似度 | ConcurrentHashMap实现 |
| FineTune | 模拟训练全生命周期 | 进度0-100%，状态流转 |
