## 🎯 模块概述

MallChat AI RAG (Retrieval-Augmented Generation) 模块是一个基于检索增强生成技术的智能问答系统，通过结合向量检索和大语言模型，为用户提供基于知识库的精准回答。

### 核心功能

1. **文档管理**：支持多种格式文档的上传、更新、删除
2. **智能检索**：基于向量相似度的语义检索（默认 Qdrant，备选 Milvus）
3. **增强生成**：结合检索结果和 LLM 生成高质量回答
4. **流式输出**：支持 SSE 流式响应，提升用户体验
5. **缓存优化**：多级缓存策略，提升系统性能
6. **降级保护**：完善的降级和容错机制
7. **Mock 模式**：无外部依赖即可启动，方便本地开发

## 🔄 核心流程

### 1. RAG 查询流程

```
用户提问
    ↓
验证请求参数
    ↓
检查索引状态（缓存）
    ↓
尝试从缓存获取查询结果
    ↓
[缓存命中] → 返回缓存结果
    ↓
[缓存未命中]
    ↓
生成问题向量（Embedding：bge/m3e）
    ↓
向量检索（Qdrant / Milvus）
    ↓
缓存检索结果
    ↓
[检索结果为空] → 降级到普通问答
    ↓
[有检索结果]
    ↓
构造 RAG Prompt（系统指令 + 上下文 + 问题）
    ↓
调用 LLM 流式生成（Qwen/Llama/OpenAI）
    ↓
流式返回结果（SSE，由 StreamController 包装）
    ↓
保存对话历史
```

### 2. 文档上传流程

```
上传文档
    ↓
验证文档格式和大小
    ↓
保存文档到存储（本地 / OSS）
    ↓
创建文档记录（MySQL，状态 PENDING）
    ↓
发送索引任务（RocketMQ）
    ↓
返回上传响应
    ↓
[异步处理]
    ↓
消费索引任务
    ↓
解析文档内容（Apache Tika）
    ↓
文档分块
    ↓
生成向量（Embedding）
    ↓
存储向量（Qdrant / Milvus）
    ↓
保存分块记录（MySQL）
    ↓
更新索引状态（COMPLETED / FAILED）
    ↓
更新缓存
```

### 3. 文档更新流程

```
更新文档
    ↓
查询旧文档
    ↓
幂等删除旧向量
    ↓
验证新文档
    ↓
保存新文档
    ↓
更新文档记录（状态 PENDING）
    ↓
发送索引任务
    ↓
清除相关缓存
    ↓
返回更新响应
```

### 4. 文档删除流程

```
删除文档
    ↓
幂等删除向量（Qdrant / Milvus）
    ↓
删除分块记录（MySQL）
    ↓
删除文档记录（MySQL）
    ↓
清除相关缓存
    ↓
返回删除响应
```

## 💾 数据模型

### 核心实体

#### 1. KnowledgeDocument（知识文档）

```java
@Data
@TableName("knowledge_document")
public class KnowledgeDocument {
    private Long id;                    // 文档ID
    private String title;               // 文档标题
    private String documentType;        // 文档类型（pdf, docx, txt等）
    private Long fileSize;              // 文件大小（字节）
    private String filePath;            // 文件路径
    private String indexStatus;         // 索引状态
    private Integer chunkCount;         // 分块数量
    private String errorMessage;        // 错误信息
    private Long uploadUserId;          // 上传用户ID
    private LocalDateTime createTime;   // 创建时间
    private LocalDateTime updateTime;   // 更新时间
}
```

#### 2. DocumentChunk（文档分块）

```java
@Data
@TableName("document_chunk")
public class DocumentChunk {
    private Long id;                    // 分块ID
    private Long documentId;            // 文档ID
    private String content;             // 分块内容
    private Integer chunkIndex;         // 分块索引
    private Integer startPosition;      // 起始位置
    private Integer endPosition;        // 结束位置
    private String metadata;            // 元数据（JSON，包含 embedding 向量）
    private LocalDateTime createTime;   // 创建时间
}
```

#### 3. AIConversation（AI对话）

```java
@Data
@TableName("ai_conversation")
public class AIConversation {
    private Long id;                    // 对话ID
    private Long userId;                // 用户ID
    private String sessionId;           // 会话ID（多轮对话）
    private String conversationType;    // 对话类型（QA / RAG / SUMMARY）
    private String userInput;           // 用户输入
    private String aiResponse;          // AI响应
    private Long documentId;            // 关联文档ID（RAG场景）/ 房间ID（QA场景复用）
    private String retrievedChunkIds;   // 检索到的分块ID列表
    private Long responseTime;          // 响应时间（毫秒）
    private LocalDateTime createTime;   // 创建时间
}
```

## 📊 性能优化

### 1. 缓存策略

#### 三级缓存架构

```
L1: 本地缓存（Caffeine）
    ↓ 未命中
L2: Redis 缓存
    ↓ 未命中
L3: 数据库查询
```

#### 缓存配置

| 缓存类型 | 过期时间 | 缓存层级 | 用途 |
|---------|---------|---------|------|
| 文档元数据 | 30分钟 | L1+L2 | 减少数据库查询 |
| 索引状态 | 10分钟 | L2 | 快速状态检查 |
| 查询结果 | 5分钟 | L2 | 热门查询优化 |

### 2. 异步处理

- 文档索引异步化（MQ）

## 🛡️ 容错设计

### 1. 降级策略

```java
// 向量库不可用 / 检索为空 → 降级到普通问答
if (searchResults.isEmpty()) {
    return fallbackToNormalQA(request, startTime);
}

// LLM 不可用 → 返回预设回复
private Flux<String> streamChatFallback(...) {
    return Flux.just("抱歉，AI服务暂时不可用，请稍后再试。");
}
```

### 2. 重试机制

- 向量检索失败重试（3次）
- LLM 调用失败重试（3次，指数退避）
- 消息发送失败重试（5次）

### 3. 熔断保护

- 外部 API 调用熔断
- 数据库连接熔断
- 缓存服务熔断
- 消息队列熔断

### 4. 超时控制

| 操作类型 | 超时时间 | 说明 |
|---------|---------|------|
| 文档解析 | 30秒 | 大文件解析 |
| 向量检索 | 5-10秒 | 向量查询 |
| LLM 调用 | 60-120秒 | 流式生成 |
| 数据库查询 | 10秒 | 复杂查询 |
