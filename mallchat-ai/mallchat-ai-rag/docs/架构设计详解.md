## 🎯 模块概述

MallChat AI RAG (Retrieval-Augmented Generation) 模块是一个基于检索增强生成技术的智能问答系统，通过结合向量检索和大语言模型，为用户提供基于知识库的精准回答。

### 核心功能

1. **文档管理**：支持多种格式文档的上传、更新、删除
2. **智能检索**：基于向量相似度的语义检索
3. **增强生成**：结合检索结果和 LLM 生成高质量回答
4. **流式输出**：支持 SSE 流式响应，提升用户体验
5. **缓存优化**：多级缓存策略，提升系统性能
6. **降级保护**：完善的降级和容错机制

## 🔄 核心流程

### 1. RAG 查询流程

```
用户提问
    ↓
验证请求参数
    ↓
检查索引状态（缓存）
    ↓
尝试从缓存获取结果
    ↓
[缓存命中] → 返回缓存结果
    ↓
[缓存未命中]
    ↓
生成问题向量（Embedding）
    ↓
向量检索（Milvus）
    ↓
缓存检索结果
    ↓
构造 RAG Prompt
    ↓
调用 LLM 流式生成
    ↓
流式返回结果（SSE）
    ↓
保存对话历史
```

### 2. 文档上传流程

```
上传文档
    ↓
验证文档格式和大小
    ↓
保存文档到存储
    ↓
创建文档记录（MySQL）
    ↓
发送索引任务（MQ）
    ↓
返回上传响应
    ↓
[异步处理]
    ↓
消费索引任务
    ↓
解析文档内容（Tika）
    ↓
文档分块
    ↓
生成向量（Embedding）
    ↓
存储向量（Milvus）
    ↓
保存分块记录（MySQL）
    ↓
更新索引状态
    ↓
更新缓存
```

### 3. 文档更新流程

```
更新文档
    ↓
查询旧文档
    ↓
幂等删除旧向量
    ↓
验证新文档
    ↓
保存新文档
    ↓
更新文档记录
    ↓
发送索引任务
    ↓
清除相关缓存
    ↓
返回更新响应
```

### 4. 文档删除流程

```
删除文档
    ↓
幂等删除向量（Milvus）
    ↓
删除分块记录（MySQL）
    ↓
删除文档记录（MySQL）
    ↓
清除相关缓存
    ↓
返回删除响应
```

```java
}

// 语义分块策略

    // 实现语义分块

```

### 2. 模板方法模式（Template Method Pattern）

**应用场景**：文档处理流程

```java
public abstract class AbstractDocumentProcessor {
    public final void process(MultipartFile file) {
        validate(file);
        String content = extract(file);
        List<DocumentChunk> chunks = chunk(content);
        store(chunks);
    }
    
    protected abstract void validate(MultipartFile file);
    protected abstract String extract(MultipartFile file);
    protected abstract List<DocumentChunk> chunk(String content);
    protected abstract void store(List<DocumentChunk> chunks);
}
```

### 3. 观察者模式（Observer Pattern）

**应用场景**：索引状态变更通知

```java
public interface IndexStatusListener {
    void onStatusChanged(Long documentId, IndexStatus newStatus);
}

public class IndexStatusNotifier {
    private List<IndexStatusListener> listeners = new ArrayList<>();
    
    public void notifyStatusChanged(Long documentId, IndexStatus newStatus) {
        listeners.forEach(listener -> 
            listener.onStatusChanged(documentId, newStatus));
    }
}
```

**应用场景**：请求验证和处理

## 📊 性能优化

### 1. 缓存策略

#### 三级缓存架构

```
L1: 本地缓存（Caffeine）
    ↓ 未命中
L2: Redis 缓存
    ↓ 未命中
L3: 数据库查询
```

#### 缓存配置

| 缓存类型 | 过期时间 | 缓存层级 | 用途 |
|---------|---------|---------|------|
| 文档元数据 | 30分钟 | L1+L2 | 减少数据库查询 |
| 索引状态 | 10分钟 | L2 | 快速状态检查 |
| 查询结果 | 5分钟 | L2 | 热门查询优化 |

## 🛡️ 容错设计

### 1. 降级策略

```java
// 向量库不可用 → 降级到普通问答
if (vectorServiceUnavailable()) {
    return fallbackToNormalQA(question);
}

// LLM 不可用 → 返回预设回复
if (llmServiceUnavailable()) {
    return degradationService.getDefaultResponse();
}
```

### 2. 重试机制

- 向量检索失败重试（3次）
- LLM 调用失败重试（2次）
- 消息发送失败重试（5次）
- 指数退避策略

### 3. 熔断保护

- 外部 API 调用熔断
- 数据库连接熔断
- 缓存服务熔断
- 消息队列熔断

### 4. 超时控制

| 操作类型 | 超时时间 | 说明 |
