# 生产环境优化指南

## 概述

本文档详细说明了 AI Assistant & RAG 系统的生产环境优化方案，包括缓存优化、批量处理、多LLM提供商支持和Milvus性能调优。

## 1. 缓存优化

### 1.1 文档元数据缓存

**实现类**: `DocumentMetadataCache`

**功能**:
- 缓存文档基本信息（标题、类型、大小、状态等）
- 支持单个和批量查询
- 自动失效和手动失效
- 两级缓存（本地 + Redis）

**缓存策略**:
- 缓存时间：30分钟
- 缓存类型：BOTH（本地 + Redis）
- 空值缓存：是（防止缓存穿透）

**使用示例**:
```java
@Autowired
private DocumentMetadataCache documentMetadataCache;

// 单个查询
KnowledgeDocument doc = documentMetadataCache.getDocumentMetadata(documentId);

// 批量查询
List<Long> ids = Arrays.asList(1L, 2L, 3L);
Map<Long, KnowledgeDocument> docs = documentMetadataCache.getDocumentMetadataBatch(ids);

// 失效缓存
documentMetadataCache.invalidateDocumentMetadata(documentId);
```

### 1.2 索引状态缓存

**实现类**: `IndexStatusCache`

**功能**:
- 缓存文档索引状态（PENDING, INDEXING, COMPLETED, FAILED）
- 支持快速查询和批量查询
- 自动过期和手动失效

**缓存策略**:
- 缓存时间：10分钟（索引状态变化较频繁）
- 缓存类型：Redis（需要跨实例共享）
- 空值缓存：否

**使用示例**:
```java
@Autowired
private IndexStatusCache indexStatusCache;

// 查询索引状态
String status = indexStatusCache.getIndexStatus(documentId);

// 检查索引是否就绪
boolean ready = indexStatusCache.isIndexReady(documentId);

// 更新索引状态
indexStatusCache.updateIndexStatus(documentId, "COMPLETED");
```

### 1.3 查询结果缓存

**实现类**: `QueryResultCache`

**功能**:
- 缓存热门查询的向量检索结果
- 减少向量数据库查询压力
- 提升响应速度

**缓存策略**:
- 缓存时间：5分钟（查询结果时效性要求较高）
- 缓存类型：Redis
- 缓存键：基于问题文本的MD5哈希

**使用示例**:
```java
@Autowired
private QueryResultCache queryResultCache;

// 尝试从缓存获取
List<SearchResult> results = queryResultCache.getQueryResult(question, documentId, topK);

if (results == null) {
    // 缓存未命中，执行检索
    results = vectorService.search(queryVector, topK, documentId);
    
    // 缓存结果
    queryResultCache.cacheQueryResult(question, documentId, topK, results);
}
```



## 2. 批量处理优化

### 2.1 批量向量生成

**实现类**: `BatchProcessingService`

**优化点**:
- 使用 LangChain4j 的 `embedAll` 方法批量生成向量
- 一次API调用生成多个向量，减少网络往返
- 支持大批量数据自动分批处理
- 支持并发处理进一步提升性能

**性能对比**:
- 循环调用：100个文本需要100次API调用
- 批量调用：100个文本只需要1-2次API调用（根据批次大小）
- 性能提升：约50-100倍

**配置参数**:
```yaml
ai:
  batch:
    embedding:
      size: 100  # 每批次向量生成数量
    database:
      size: 500  # 每批次数据库操作数量
    concurrent:
      threads: 4  # 并发处理线程数
```

**使用示例**:
```java
@Autowired
private BatchProcessingService batchProcessingService;

// 批量生成向量（自动分批）
List<String> texts = Arrays.asList("text1", "text2", ...);
List<float[]> embeddings = batchProcessingService.batchGenerateEmbeddings(texts);

// 并发批量生成（高性能版本）
List<float[]> embeddings = batchProcessingService.concurrentBatchGenerateEmbeddings(texts);
```

### 2.2 批量数据库操作

**优化点**:
- 使用 MyBatis-Plus 的 `saveBatch` 方法批量插入
- 减少数据库连接次数
- 提升写入性能

**性能对比**:
- 单条插入：1000条数据需要1000次数据库操作
- 批量插入：1000条数据只需要2-5次数据库操作
- 性能提升：约200-500倍

### 2.3 批量向量存储

**优化点**:
- Milvus 原生支持批量插入
- 一次性插入多个向量，减少网络开销
- 自动处理大批量数据分批

**实现位置**: `MilvusVectorService.storeVectors()`

### 3.2 提供商切换

**实现类**: `LLMServiceFactory`

**功能**:
- 管理多个 LLM 提供商
- 根据配置动态切换
- 支持降级和故障转移
- 支持运行时切换

**配置示例**:
```yaml
langchain4j:
  llm:
    provider: openai  # 默认提供商
    fallback-provider: claude  # 降级提供商
  
  # OpenAI 配置
  openai:
    api-key: sk-xxx
    model-name: gpt-3.5-turbo
    
  # Claude 配置
  claude:
    api-key: sk-ant-xxx
    model-name: claude-3-opus-20240229
```

**使用示例**:
```java
@Autowired
private LLMServiceFactory llmServiceFactory;

// 获取默认服务
LLMService service = llmServiceFactory.getDefaultService();

// 获取指定提供商服务
LLMService openaiService = llmServiceFactory.getService(LLMProvider.OPENAI);
LLMService claudeService = llmServiceFactory.getService(LLMProvider.CLAUDE);

// 获取降级服务
LLMService fallbackService = llmServiceFactory.getFallbackService();

// 运行时切换提供商
llmServiceFactory.switchDefaultProvider(LLMProvider.CLAUDE);
```



## 4. Milvus 性能调优

### 4.1 连接池管理

**实现类**: `MilvusConnectionPool`

**功能**:
- 管理 Milvus 客户端连接池
- 复用连接，减少连接开销
- 支持连接健康检查
- 自动重连机制

**配置参数**:
```yaml
milvus:
  host: localhost
  port: 19530
  connect-timeout: 10
  keep-alive-time: 55
  keep-alive-timeout: 20
  
  # 连接池配置
  pool:
    min-size: 2    # 最小连接数
    max-size: 10   # 最大连接数
    acquire-timeout: 30  # 获取连接超时时间（秒）
```

**使用示例**:
```java
@Autowired
private MilvusConnectionPool connectionPool;

// 获取连接
MilvusServiceClient client = connectionPool.acquireConnection();

try {
    // 使用连接执行操作
    client.search(...);
} finally {
    // 归还连接
    connectionPool.releaseConnection(client);
}

// 查看连接池状态
PoolStats stats = connectionPool.getPoolStats();
log.info("Pool stats: {}", stats);
```

### 4.2 索引参数优化

**索引类型选择**:

| 索引类型 | 适用场景 | 性能 | 内存占用 |
|---------|---------|------|---------|
| **IVF_FLAT** | 中小规模数据（< 100万） | 中 | 低 |
| **IVF_SQ8** | 大规模数据，内存受限 | 中 | 很低 |
| **HNSW** | 高性能要求，内存充足 | 高 | 高 |
| **IVF_PQ** | 超大规模数据 | 低 | 很低 |

**推荐配置**:

1. **开发/测试环境**:
```yaml
milvus:
  collection:
    index-type: IVF_FLAT
    metric-type: L2
    index-params:
      nlist: 128  # 聚类中心数量
    search-params:
      nprobe: 10  # 搜索的聚类数量
```

2. **生产环境（中等规模）**:
```yaml
milvus:
  collection:
    index-type: IVF_FLAT
    metric-type: L2
    index-params:
      nlist: 1024
    search-params:
      nprobe: 16
```

3. **生产环境（大规模）**:
```yaml
milvus:
  collection:
    index-type: HNSW
    metric-type: L2
    index-params:
      M: 16        # 每个节点的最大连接数
      efConstruction: 200  # 构建时的搜索深度
    search-params:
      ef: 64       # 搜索时的深度
```

## 6. 面试准备

### 6.1 核心技术点

**1. 缓存设计**:
- **问题**: 如何设计多级缓存系统？
- **回答**: 
  - 本地缓存（Caffeine）：热点数据，毫秒级响应
  - Redis缓存：共享数据，跨实例访问
  - 数据库：持久化存储
  - 缓存策略：LRU淘汰，TTL过期，主动失效

**2. 批量处理优化**:
- **问题**: 如何优化大批量数据处理？
- **回答**:
  - API层面：使用批量接口减少网络往返
  - 数据库层面：批量插入减少事务开销
  - 并发处理：使用线程池并发执行
  - 内存控制：分批处理避免OOM

**3. 向量数据库优化**:
- **问题**: Milvus 如何进行性能调优？
- **回答**:
  - 索引选择：根据数据规模选择合适索引（IVF_FLAT, HNSW）
  - 参数调优：nlist, nprobe, M, ef 等参数
  - 连接池：复用连接减少开销
  - 分片副本：提升并发和可用性

**4. 多提供商支持**:
- **问题**: 如何设计支持多个LLM提供商的系统？
- **回答**:
  - 抽象接口：定义统一的 LLMService 接口
  - 工厂模式：使用工厂管理不同实现
  - 配置驱动：通过配置文件切换提供商
  - 降级策略：主提供商失败时自动切换

### 6.2 系统设计问题

**问题1**: 如何设计一个高性能的RAG系统？

**回答要点**:
1. **架构设计**:
   - 分层架构：API层、服务层、数据层
   - 异步处理：文档索引异步化
   - 流式输出：提升用户体验

2. **性能优化**:
   - 缓存：多级缓存减少查询
   - 批量处理：减少API调用
   - 连接池：复用数据库连接
   - 并发控制：合理使用线程池

3. **可靠性保障**:
   - 重试机制：API调用失败重试
   - 熔断降级：服务不可用时降级
   - 监控告警：实时监控关键指标
   - 日志追踪：完整的请求链路

**问题2**: 缓存一致性如何保证？

**回答要点**:
1. **更新策略**:
   - Cache Aside：先更新数据库，再删除缓存
   - Write Through：同时更新数据库和缓存
   - Write Behind：先更新缓存，异步更新数据库

2. **失效策略**:
   - 主动失效：数据更新时主动删除缓存
   - 被动失效：设置TTL自动过期
   - 延迟双删：删除缓存后延迟再删一次

3. **分布式一致性**:
   - Redis Pub/Sub：通知其他实例失效缓存
   - 版本号：使用版本号检测数据变化
   - 最终一致性：接受短暂的不一致

### 6.3 代码实现细节

**1. 批量向量生成实现**:
```java
public List<float[]> batchGenerateEmbeddings(List<String> texts) {
    // 分批处理，避免单次请求过大
    List<float[]> allEmbeddings = new ArrayList<>();
    
    for (int i = 0; i < texts.size(); i += batchSize) {
        int endIndex = Math.min(i + batchSize, texts.size());
        List<String> batch = texts.subList(i, endIndex);
        
        // 使用批量API
        List<float[]> batchEmbeddings = embeddingService.generateEmbeddings(batch);
        allEmbeddings.addAll(batchEmbeddings);
    }
    
    return allEmbeddings;
}
```

**2. 连接池实现**:
```java
public MilvusServiceClient acquireConnection() throws InterruptedException {
    // 从池中获取连接
    MilvusServiceClient client = connectionPool.poll(timeout, TimeUnit.SECONDS);
    
    if (client == null) {
        // 池为空且未达上限，创建新连接
        if (connectionPool.size() < maxPoolSize) {
            client = createConnection();
        } else {
            throw new IllegalStateException("Connection pool exhausted");
        }
    }
    
    // 健康检查
    if (!isConnectionHealthy(client)) {
        closeConnection(client);
        client = createConnection();
    }
    
    return client;
}
```

**3. 缓存查询实现**:
```java
public KnowledgeDocument getDocumentMetadata(Long documentId) {
    // 先查缓存
    String cacheKey = "doc:meta:" + documentId;
    KnowledgeDocument cached = cache.get(cacheKey);
    
    if (cached != null) {
        return cached;
    }
    
    // 缓存未命中，查数据库
    KnowledgeDocument doc = documentDao.getById(documentId);
    
    // 写入缓存
    if (doc != null) {
        cache.put(cacheKey, doc, 30, TimeUnit.MINUTES);
    }
    
    return doc;
}
```
