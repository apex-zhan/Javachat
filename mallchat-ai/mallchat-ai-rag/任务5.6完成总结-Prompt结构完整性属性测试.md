### Test Coverage

The property test validates that RAG prompts contain all required components and are properly formatted:

#### 1. **Main Property Test** (tries = 100)
- **Property 20: Prompt Structure Completeness**
- Validates that every RAG prompt contains:
  - System instruction (系统指令)
  - Retrieved context (检索上下文/知识库内容)
  - User question (用户问题)

#### 2. **Format Correctness** (tries = 100)
- Validates proper section ordering:
  - System instruction comes first
  - Knowledge base section comes second
  - User question comes last
- Validates section separators are present (`---`)

#### 3. **Context Ordering** (tries = 100)
- Validates search results are ordered by similarity score (descending)
- Validates results appear in the prompt in the correct order

#### 4. **Deduplication** (tries = 100)
- Validates duplicate content is removed from the prompt
- Ensures each unique content appears exactly once

#### 5. **Score Display** (tries = 100)
- Validates similarity scores are displayed for each result
- Format: `(相似度: X.XX)`

#### 6. **Fragment Numbering** (tries = 100)
- Validates search results are numbered sequentially
- Format: `[片段 1]`, `[片段 2]`, etc.

#### 7. **Empty Results Handling** (tries = 50)
- Validates fallback behavior when no search results are found
- Ensures system instruction and question are still present

#### 8. **Question Preservation** (tries = 100)
- Validates user question is preserved exactly as provided
- No modification or truncation of the original question

### Test Implementation Approach

#### Helper Methods
The test includes a copy of the `buildRAGPrompt` method from `RAGServiceImpl` to enable isolated testing without requiring the full service context. This approach:
- Allows testing the prompt construction logic independently
- Avoids complex mocking of dependencies
- Ensures the test validates the actual prompt structure

#### Arbitraries (Data Generators)
- `validQuestion()`: Generates questions (10-200 characters)
- `validSearchResults()`: Generates 1-5 search results
- `multipleSearchResults()`: Generates 2-10 search results
- `searchResultsWithDuplicates()`: Generates results with intentional duplicates
- `searchResult()`: Generates individual search results with realistic data

### Validation Strategy

Each property test validates specific aspects of the prompt structure:

1. **Content Presence**: Uses `assertThat().contains()` to verify required sections
2. **Ordering**: Uses index comparison to verify section order
3. **Deduplication**: Counts occurrences to ensure uniqueness
4. **Format**: Uses pattern matching to verify formatting conventions

## Testing Notes

### Why Copy buildRAGPrompt?
The test includes a copy of the `buildRAGPrompt` method from `RAGServiceImpl` because:
1. **Isolation**: Tests the prompt construction logic without service dependencies
2. **Simplicity**: Avoids complex mocking of LLMService, VectorService, etc.
3. **Clarity**: Makes the test self-contained and easier to understand
4. **Maintainability**: If the actual implementation changes, the test can be updated independently

### Deduplication Logic
The test also includes the `deduplicateSearchResults` method to ensure consistent behavior with the actual implementation. This validates that:
- Duplicate content is identified correctly
- Higher-scored duplicates are preferred
- Results are sorted by score after deduplication
