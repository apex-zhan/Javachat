## Implementation Details

### 核心组件

1. **StreamChunk** - 流式数据块模型
   ```java
   - index: Integer          // 分块序号
   - content: String         // 内容片段
   - finished: Boolean       // 是否结束
   - error: String          // 错误信息
   - timestamp: Long        // 时间戳
   ```

2. **StreamController** - SSE控制器
   - 端点：`POST /api/stream/rag/query`
   - 响应类型：`text/event-stream`
   - 事件类型：message, done, error, heartbeat, timeout

3. **StreamConnectionManager** - 连接管理器
   - 跟踪活跃连接
   - 超时检测和清理
   - 资源管理

### 流式输出流程

```
客户端请求
    ↓
生成连接ID
    ↓
注册连接
    ↓
开始流式响应
    ↓
发送内容块（event: message）
    ↓
定期发送心跳（event: heartbeat）
    ↓
更新连接活跃时间
    ↓
发送结束标记（event: done, finished: true）
    ↓
注销连接
    ↓
释放资源
```

### 错误处理

1. **参数验证错误**
   - 返回 error 事件
   - 包含友好的错误消息

2. **处理过程错误**
   - 捕获异常
   - 返回 error 事件
   - 标记 finished=true

3. **连接超时**
   - 发送 timeout 事件
   - 自动关闭连接
   - 释放资源

4. **客户端取消**
   - 触发 doOnCancel 钩子
   - 注销连接
   - 释放资源

### 性能优化

1. **心跳间隔**：30秒（避免频繁发送）
2. **超时时间**：300秒（5分钟）
3. **超时检测间隔**：60秒（定期清理）
4. **连接跟踪**：使用 ConcurrentHashMap（线程安全）

## API Documentation

### POST /api/stream/rag/query

**描述**：流式RAG查询接口

**请求体**：
```json
{
  "question": "用户问题",
  "userId": 123,
  "documentId": 456,
  "topK": 5
}
```

**响应类型**：`text/event-stream`

**事件类型**：

1. **message** - 内容块
   ```json
   {
     "index": 0,
     "content": "回答内容片段",
     "finished": false,
     "timestamp": 1704614400000
   }
   ```

2. **done** - 结束标记
   ```json
   {
     "index": 10,
     "content": "",
     "finished": true,
     "timestamp": 1704614410000
   }
   ```

3. **error** - 错误事件
   ```json
   {
     "index": 5,
     "content": "",
     "finished": true,
     "error": "错误信息",
     "timestamp": 1704614405000
   }
   ```

4. **heartbeat** - 心跳消息
   ```json
   {
     "index": -1,
     "content": "",
     "finished": false,
     "timestamp": 1704614430000
   }
   ```

5. **timeout** - 超时事件
   ```json
   {
     "index": 8,
     "content": "",
     "finished": true,
     "error": "连接超时",
     "timestamp": 1704614700000
   }
   ```
