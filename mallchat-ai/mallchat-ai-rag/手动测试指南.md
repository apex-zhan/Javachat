# RAG系统手动测试指南

## 测试目标
验证核心RAG功能的完整流程：文档上传 → 等待索引 → 执行查询 → 获得流式回答

## 前置条件检查清单

### 1. 基础设施
- [ ] MySQL数据库已启动并创建表结构
- [ ] Milvus向量数据库已启动（端口19530）
- [ ] RocketMQ消息队列已启动
- [ ] Redis缓存已启动（如果启用）

### 2. 配置检查
- [ ] OpenAI API密钥已配置（环境变量或配置文件）
- [ ] Milvus连接配置正确
- [ ] RocketMQ连接配置正确
- [ ] 文档存储路径已创建（./uploads/documents）

### 3. 数据库表结构
运行以下SQL确保表结构存在：

```sql
-- 检查表是否存在
SHOW TABLES LIKE 'ai_%';

-- 应该看到以下表：
-- ai_knowledge_document
-- ai_document_chunk
-- ai_conversation
```

如果表不存在，运行：`docs/ai-tables.sql`

### 4. 启动应用
```bash
# 启动MallChat应用
cd mallchat-chat-server
mvn spring-boot:run -Dspring.profiles.active=local,ai
```

检查启动日志，确保：
- LangChain4j配置加载成功
- Milvus连接成功
- RocketMQ连接成功

### 测试2: 等待索引完成

#### 2.1 轮询索引状态
```bash
# 每隔2秒检查一次索引状态
while true; do
  curl http://localhost:8080/api/documents/1/status
  echo ""
  sleep 2
done
```

#### 2.2 观察状态变化
**预期状态变化**：
1. `PENDING` → 等待处理
2. `INDEXING` → 正在索引
3. `COMPLETED` → 索引完成

**超时时间**：
- 小文档（<1KB）：应在10秒内完成
- 中等文档（1-10KB）：应在30秒内完成
- 大文档（>10KB）：应在60秒内完成

#### 2.3 检查索引结果
```sql
-- 查询文档状态
SELECT id, title, index_status, chunk_count, error_message, update_time
FROM ai_knowledge_document
WHERE id = 1;

-- 查询分块记录
SELECT id, document_id, chunk_index, LENGTH(content) as content_length, 
       token_count, vector_id, create_time
FROM ai_document_chunk
WHERE document_id = 1
ORDER BY chunk_index;
```

**预期结果**：
- index_status = 'COMPLETED'
- chunk_count > 0（根据文档大小）
- error_message为NULL
- 分块记录数量 = chunk_count
- 每个分块都有vector_id

#### 2.4 检查Milvus向量
```python
# 使用Python脚本检查Milvus中的向量
from pymilvus import connections, Collection

# 连接Milvus
connections.connect(host="localhost", port="19530")

# 获取Collection
collection = Collection("mallchat_knowledge_vectors")

# 查询向量数量
print(f"Total vectors: {collection.num_entities}")

# 查询特定文档的向量
results = collection.query(
    expr="document_id == 1",
    output_fields=["document_id", "chunk_id", "chunk_index"]
)
print(f"Document 1 vectors: {len(results)}")
```

**预期结果**：
- 向量数量 > 0
- 向量数量 = chunk_count

## 性能测试

### 1. 首字延迟（TTFB）
测量从发送请求到收到第一个字符的时间：

```bash
time curl -X POST http://localhost:8080/api/documents/query \
  -H "Content-Type: application/json" \
  -d '{
    "question": "MallChat有哪些主要功能？",
    "documentId": 1,
    "userId": 1,
    "topK": 5
  }' | head -c 1
```

**目标**：< 500ms

### 2. 向量检索延迟
查看日志中的检索耗时：

```bash
grep "向量检索完成" logs/mallchat-chat-server/mallchat-chat-server.log | tail -10
```

**目标**：< 100ms

### 3. 端到端延迟
测量完整查询的总耗时：

```bash
time curl -X POST http://localhost:8080/api/documents/query \
  -H "Content-Type: application/json" \
  -d '{
    "question": "MallChat有哪些主要功能？",
    "documentId": 1,
    "userId": 1,
    "topK": 5
  }' > /dev/null
```

**目标**：< 5s（取决于LLM响应速度）

### 4. 并发测试
使用Apache Bench进行并发测试：

```bash
# 10个并发用户，总共100个请求
ab -n 100 -c 10 -p query.json -T application/json \
  http://localhost:8080/api/documents/query
```

**目标**：
- 成功率 > 95%
- 平均响应时间 < 5s
- 无内存泄漏

## 常见问题排查

### 问题1：索引一直处于PENDING状态
**可能原因**：
- RocketMQ消费者未启动
- 消息发送失败
- 消费者处理异常

**排查步骤**：
1. 检查RocketMQ是否运行
2. 检查消费者日志
3. 检查消息队列中是否有积压

### 问题2：向量检索返回空结果
**可能原因**：
- 向量未成功存储到Milvus
- 相似度阈值过高
- 查询向量生成失败

**排查步骤**：
1. 检查Milvus中是否有向量
2. 降低相似度阈值测试
3. 检查Embedding服务是否正常

### 问题3：LLM响应超时
**可能原因**：
- OpenAI API网络问题
- API密钥无效
- 请求过于频繁被限流

**排查步骤**：
1. 检查网络连接
2. 验证API密钥
3. 检查API调用日志
4. 增加超时时间

### 问题4：流式响应中断
**可能原因**：
- 客户端连接断开
- 服务器超时
- LLM API异常

**排查步骤**：
1. 检查客户端连接状态
2. 检查服务器日志
3. 检查LLM API状态
